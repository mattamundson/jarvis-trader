Trade Approval System

P0 BLOCKER ~8 hours

Every trade requires Matt's approval. The Fund Manager agent flags requires_human_approval=True but there is no queue, no API to approve/reject, and no UI. This is the #1 blocker.

Add migration to _ensure_tables() in database/migrations.py SQLite CREATE TABLE IF NOT EXISTS. Include indexes on status and created_at for fast pending-queue lookups.

Create POST /approvals/{approval_id}/reject endpoint Sets status=REJECTED, reviewed_at=now(), reviewed_by='Matt', includes optional rejection_reason text field. Does NOT submit any order. Logs to audit trail.

Auto-expire stale approvals after 60 minutes Add a background task (APScheduler job) that sets status=EXPIRED for any PENDING approval older than 60 minutes. Market conditions change — a signal from an hour ago is stale.

The pipeline generates signals and the safety layer validates orders, but the actual execution path from "approved signal" → "order submitted to IB Gateway" has gaps. The scheduler only logs — it doesn't trigger the pipeline on market data.

2.1 Enable Paper Simulated Orders
engine/.env (MODIFY)
Set ALLOW_PAPER_SIMULATED_ORDERS=True in .env This flag in TradingConfig controls whether check_order() allows paper-mode orders to pass the gating check. Currently False — orders are rejected with "Live trading is disabled." Setting True lets paper orders through safety checks while LIVE_TRADING_ENABLED remains False.
Verify safety layer behavior with this flag Run: cd engine && .venv/Scripts/python -m pytest tests/test_safety_layer.py -v. Confirm all tests pass. The safety layer test suite must remain green after this change.
Verify kill switch still activates at -2% daily / -10% drawdown Even with ALLOW_PAPER_SIMULATED_ORDERS=True, the kill switch checks (checks 3 & 4) must still fire. Write a quick integration test to confirm.
2.2 Market Scan Scheduler
engine/schedulers/market_scanner.py (NEW)
Create MarketScanScheduler — runs every 30 minutes during RTH APScheduler cron job: Mon-Fri, 9:30 AM to 3:30 PM CT, every 30 minutes. For each symbol in FUTURES_WATCHLIST (MCL, MNQ): fetch latest 1h bars from Polygon.io, run generate_instrument_signals(), check if entry_signal == 'ENTRY_NOW'.

If ENTRY_NOW: submit to TradingPipeline.run() for AI validation Don't submit the order directly — feed the signal through the full 5-stage AI pipeline. The pipeline's Fund Manager will flag requires_human_approval, which creates the pending approval record (from WS1).

Register MarketScanScheduler in main.py lifespan startup Alongside the existing EODScheduler. Add configuration toggle ENABLE_MARKET_SCANNER=True in .env so it can be disabled during development.

Trade Lifecycle & Validation Tracking

P2 ~5 hours

Once trades are executing, we need to track the full lifecycle: entry → stop management → target hits → exit → outcome recording → validation metric update. The learning system also needs trade outcomes to provide feedback.

8.1 Trade Exit Management
Implement tiered exit logic: 50% at T1, 25% at T2, 25% at T3 When a paper position hits T1, automatically close 50% of the position. Move stop to breakeven. This requires monitoring position vs live price. Can be done in the market scanner loop: for each open position, check if current price has hit T1/T2/T3 or stop.
Implement breakeven stop movement after T1 hit When 50% is closed at T1, update the stop_level on the remaining position to the entry price. Log the stop adjustment.
Implement trailing stop to T1 after T2 hit When 25% is closed at T2, trail the stop on remaining 25% up to T1 level. This locks in a minimum profit on the remaining piece.
Implement end-of-day forced exit At 3:00 PM CT, check all open positions against overnight hold criteria. Close positions that don't qualify. For those that qualify, require Matt's explicit approval for overnight hold (via approval queue).
Add overnight hold approval type to approval system New approval type: OVERNIGHT_HOLD. Shows: current P&L, current price vs entry, stop distance, next day's economic calendar, regime status. Matt approves or closes the position.
8.2 Trade Outcome Recording
Record trade outcome when position is fully closed Write to paper_trades table: entry_time, exit_time, entry_price, exit_price, quantity, side, realized_pnl, R_multiple (profit/initial_risk), signal_type (A/B/C/D from strategy), regime at entry, bias at entry.
Update SafetyLayer loss tracker with trade result Call safety_layer.record_trade_result(symbol, pnl) after each trade close. This feeds the consecutive loss tracker for tilt protection.
Update 30-day validation metrics after each trade Recompute: win rate, profit factor, Sharpe ratio, max drawdown, total trade count. Compare against targets. If any metric crosses a target threshold (either direction), log it.
8.3 Learning System Feed
Feed trade outcomes to learning/trade_classifier.py After each trade closes, call the trade classifier to grade it A-F. Store the grade with the trade record. This builds the dataset for pattern recognition.
Run pattern_extractor.py weekly on accumulated trades After 1 week of trading, run pattern extraction: time-of-day patterns, regime-based win rates, streak analysis. Store results for review. DO NOT auto-tune — this is observational only during Phase 1.
Add learning insights to weekly WhatsApp summary The Friday 3:30 PM weekly summary should include: trade grades distribution (how many A vs B vs C vs F), best performing regime, worst performing time window, any streak alerts.
8.4 Validation Dashboard
Wire validation progress page to live data The /validation page should show real-time progress against all 6 gates: PF, Sharpe, WR, trade count, days, max DD. Each gate should show current value, target value, and pass/fail status with color coding.
Add daily equity curve chart Line chart showing daily ending equity from day 1 to current day. X-axis = trading days, Y-axis = equity ($). Show drawdown periods as shaded red regions.
Add trade-by-trade scatter plot Each trade as a dot. X-axis = trade number, Y-axis = R-multiple. Color: green if positive, red if negative. Helps visualize streaks and outliers.
