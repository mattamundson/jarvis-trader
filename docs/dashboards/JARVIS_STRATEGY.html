The Thesis

This is not a "system." It is a decision architecture that fuses the quantitative edge of Steven Cohen's multi-signal validation with the engineering discipline of Tony Stark's layered defense systems. Every trade must pass through five independent layers of confirmation before a single contract is risked. The AI doesn't generate alpha — the indicators generate alpha. The AI validates, debates, and stress-tests the signal before execution.

The core insight: markets are not random, but they are adversarial. The edge comes not from predicting the future, but from entering only when five independent systems agree that the present moment is asymmetrically favorable — and sizing the bet to survive being wrong.

Three Operating Principles

1. Never Bet on One Signal (Cohen)

No trade fires on a single indicator. The standard signal requires STC momentum alignment plus regime confirmation plus structural confirmation plus directional bias from 4 independent sources. The composite MES strategy adds ORB and VWAP reversion on top. A single indicator can be gamed; five agreeing simultaneously is a statistical event worth betting on.

2. Layered Defense Architecture (Stark)

Each of the five layers acts as an independent filter. Layer 1 (Regime) sets the environment. Layer 2 (Structure) identifies where price sits relative to auction theory. Layer 3 (Bias) aggregates four directional votes. Layer 4 (Entry) waits for the exact trigger. Layer 5 (Sizing) calibrates the bet to survive worst-case scenarios. An entry requires ALL five layers to be permissive — any single layer can veto.

3. The AI is the Risk Manager, Not the Trader

The mechanical signal system generates entries. The 10-agent AI pipeline then debates the entry — bull vs. bear researchers present opposing cases, the trader synthesizes, the risk manager validates, and the fund manager gives final approval. The AI's job is to reject bad signals, not to find signals the math missed. This is the difference between an AI copilot and an AI pilot.

Layer 1 — Regime Map

What environment are we in?

Layer 1 classifies the current market environment from four computed inputs. Each input is derived from raw OHLCV bars:

Input 1: ATR Range Consumed %

ATR_consumed = |close - prior_close| / ATR * 100

where ATR = Wilder's Average True Range (period=14):
  TR[i] = max(high - low, |high - prior_close|, |low - prior_close|)
  ATR[14] = mean(TR[0..13])
  ATR[i] = (ATR[i-1] * 13 + TR[i]) / 14    (Wilder smoothing)

Example: MCL close=69.20, prior_close=68.80, ATR=0.45
  consumed = |69.20 - 68.80| / 0.45 * 100 = 88.9%
  Interpretation: 88.9% of the expected daily range has been used up

Why it matters: If price has already moved 90%+ of its expected range, there's little fuel left. Entering a trend trade when the move is nearly spent is a losing proposition.

Input 2: Phase Oscillator

Phase = (close - EMA21) / (3 * ATR) * 100, clamped to [-100, +100]

where EMA21 = exponential moving average of close, span=21

Example: close=69.20, EMA21=68.90, ATR=0.45
  Phase = (69.20 - 68.90) / (3 * 0.45) * 100 = 22.2
  Interpretation: price is 22.2% of a normalized range above its mean

Why it matters: Phase tells you how far price has deviated from its mean, in volatility-adjusted terms. Fibonacci zones at +/-23.6, +/-61.8, +/-100 mark increasing levels of extension. Extreme readings (> 61.8) signal exhaustion.

Input 3: Phase Compression

BB_width = (SMA20 + 2*stddev) - (SMA20 - 2*stddev) = 4 * rolling_stddev(close, 21)
ATR_band_width = 2 * ATR

Compression = True when BB_width < ATR_band_width
  i.e., when 4 * stddev < 2 * ATR → stddev < 0.5 * ATR

Interpretation: realized volatility (stddev) has contracted to less
than half of expected volatility (ATR). The market is coiling.

Why it matters: Compression precedes expansion. But you can't predict which direction the expansion will go. So compression = don't enter, wait for the breakout.

Input 4: EMA Ribbon Trend

EMA8  = EWM(close, span=8)
EMA21 = EWM(close, span=21)
EMA34 = EWM(close, span=34)

IF EMA8 > EMA21 > EMA34 → "bullish"  (all three aligned upward)
IF EMA8 < EMA21 < EMA34 → "bearish"  (all three aligned downward)
ELSE                     → "neutral"  (tangled — no clear trend)

Why it matters: Three timeframes of momentum stacked in order means the short, medium, and long-term trends agree. When they don't agree, it's chop.

The Regime Decision Tree

IF consumed > 90%
  → EXHAUSTED // move is spent, block new entries
ELIF compression == True AND consumed < 50%
  → COMPRESSION // volatility coiling, wait for breakout
ELIF ema_trend == "bullish" AND consumed < 70% AND phase > 0
  → TRENDING_BULL // room to run + aligned trend + above mean
ELIF ema_trend == "bearish" AND consumed < 70% AND phase < 0
  → TRENDING_BEAR // room to run + aligned trend + below mean
ELSE
  → RANGE_BOUND // mixed signals, no clear environment

Layer 2 — Structure Map

Where is price relative to value?

Layer 2 determines whether price is inside or outside the "value area" — the zone where most trading activity occurred recently. This is rooted in auction market theory: price that moves away from value and is accepted there (doesn't snap back) signals a shift in perceived fair value.

Input 1: VPOC (Volume Point of Control)

VPOC = rolling 20-bar Volume-Weighted Average Price

VPOC[i] = sum(close[j] * volume[j], j=i-19..i) / sum(volume[j], j=i-19..i)

Example: 20 bars of MCL data, total close*vol = 14,280,000, total vol = 210,000
  VPOC = 14,280,000 / 210,000 = 68.00

Interpretation: the price where the MOST volume transacted.
This is "fair value" — where buyers and sellers agreed most.

Note: True VPOC requires tick-level data (TPO profiles). This VWAP proxy is the best approximation from hourly OHLCV bars. It captures the volume-weighted center of gravity of the last 20 bars.

Input 2: VAH / VAL (Value Area High / Low)

VAH = 85th percentile of the last 20 bars' highs
VAL = 15th percentile of the last 20 bars' lows

Calculation: sort last 20 high values ascending, take value at position 17 (85%)
             sort last 20 low values ascending, take value at position 3 (15%)

Example: 20 bars of MCL
  Sorted highs: [67.80, 68.00, ..., 69.30, 69.50]
  VAH = 85th pctile ≈ 69.30
  Sorted lows: [67.20, 67.40, ..., 68.90, 69.10]
  VAL = 15th pctile ≈ 67.40

Value Area = [67.40, 69.30]  (70% of price action happened here)
  Price above 69.30 = above value → potential buyer control
  Price below 67.40 = below value → potential seller control
  Price between 67.40-69.30 = inside value → neutral

Why 85th/15th percentile? This captures the central 70% of price action (from 15th to 85th), which mirrors the classic TPO Value Area definition (70% of TPO letters).

Input 3: IB High / IB Low (Initial Balance)

For hourly backtesting:
  IB_HIGH = prior bar's high
  IB_LOW  = prior bar's low

For live intraday (minute data):
  IB_HIGH = max(high[bar]) for bars from 9:30 to 10:30 AM ET
  IB_LOW  = min(low[bar]) for bars from 9:30 to 10:30 AM ET
  IB_RANGE = IB_HIGH - IB_LOW

Extension targets (from live IB):
  ext_50_up   = IB_HIGH + 0.50 * IB_RANGE
  ext_100_up  = IB_HIGH + 1.00 * IB_RANGE
  ext_300_up  = IB_HIGH + 3.00 * IB_RANGE
  (mirror for downside)

Example: MCL RTH opens, first hour trades 68.40 to 69.10
  IB_HIGH = 69.10, IB_LOW = 68.40, IB_RANGE = 0.70
  50% extension target up   = 69.10 + 0.35 = 69.45
  100% extension target up  = 69.10 + 0.70 = 69.80
  3x extension target up    = 69.10 + 2.10 = 71.20

Why IB matters: The first 60 minutes of RTH is when institutional order flow establishes the session's initial range. A breakout from this range is a statistically significant event — it means the market rejected the initial price discovery and is repricing. 80% of trending days show IB breakout in the first 2 hours.

The Structure Decision

above_vah     = (close > VAH)       // price left value area to the upside
below_val     = (close < VAL)       // price left value area to the downside
above_ib_high = (close > IB_HIGH)   // price broke above initial balance
below_ib_low  = (close < IB_LOW)    // price broke below initial balance
IF above_vah == True AND above_ib_high == True
  → BUYER_CONTROL
  // Price is above where 70% of volume traded AND above the session range.
  // Two independent structural signals agree: genuine buyer acceptance.

ELIF below_val == True AND below_ib_low == True
  → SELLER_CONTROL
  // Price is below value AND below session range. Sellers drove it out.

ELSE
  → NEUTRAL_STRUCTURE
  // Inside value area, or mixed (above VAH but inside IB, etc).
  // No structural edge. Require STC crossover for entry.

Why BOTH conditions? Being above VAH alone could be a brief spike that snaps back. Being above IB High alone could be noise in a wide IB range. But being above both means: (1) price left the zone where 70% of volume traded, AND (2) it broke beyond the session's opening range. The conjunction of two independent structural signals is what distinguishes genuine acceptance from a wick.

Layer 3 — Directional Bias

Which way should we lean?

Layer 3 polls four mathematically independent indicators. Each one captures a different market dynamic. Each casts a vote: bull (+1), bear (+1), or abstain (0). The tally determines directional bias.

Voter 1: KAMA — Kaufman Adaptive Moving Average (period=10)

Efficiency Ratio (ER):
  ER = |close - close[10 bars ago]| / sum(|close[i] - close[i-1]|, last 10 bars)
  Range: 0.0 (pure chop) to 1.0 (straight-line trend)

Smoothing Constant (SC):
  fast_sc = 2 / (2 + 1) = 0.667    (fast EMA weighting)
  slow_sc = 2 / (30 + 1) = 0.0645  (slow EMA weighting)
  SC = (ER * (fast_sc - slow_sc) + slow_sc)^2

KAMA:
  KAMA[i] = KAMA[i-1] + SC * (close[i] - KAMA[i-1])

Vote:
  IF close > KAMA → BULL (+1)   // price above adaptive trend
  IF close < KAMA → BEAR (+1)   // price below adaptive trend

Example: MCL close=69.20, KAMA=68.95 → close > KAMA → BULL vote

Why KAMA, not a simple MA? KAMA speeds up in trends (ER near 1.0 → SC is large → tracks price closely) and slows down in chop (ER near 0.0 → SC is tiny → barely moves). This means it doesn't whipsaw in ranging markets but reacts fast to real moves. It's an adaptive momentum filter.

Voter 2: STC — Schaff Trend Cycle Direction

MACD = EMA(close, 23) - EMA(close, 50)

First Stochastic of MACD:
  K1 = (MACD - lowest(MACD, 10)) / (highest(MACD, 10) - lowest(MACD, 10)) * 100
  D1 = EMA(K1, 3)

Second Stochastic of D1:
  K2 = (D1 - lowest(D1, 10)) / (highest(D1, 10) - lowest(D1, 10)) * 100
  STC = EMA(K2, 3), clamped [0, 100]

STC Direction:
  IF STC < OS (15) → "oversold"
  IF STC > OB (83/92) → "overbought"
  IF STC > STC_prev → "rising"
  IF STC < STC_prev → "falling"

Vote:
  IF oversold OR rising → BULL (+1)   // momentum favors upside
  IF overbought OR falling → BEAR (+1)  // momentum favors downside

Example: STC=12.5 (below OS=15) → "oversold" → BULL vote

Why double-stochastic of MACD? MACD captures momentum as the spread between a fast and slow EMA. Applying stochastic twice smooths out noise while preserving inflection points. The result oscillates 0-100 and spends most time near 0 or 100 — the crossings of the OS/OB thresholds are the high-probability signals.

Voter 3: Volume Stack — Who's Actually Trading?

buy_volume  = volume * (close - low) / (high - low)
sell_volume = volume * (high - close) / (high - low)
buy_pct     = buy_volume / (buy_volume + sell_volume) * 100

Logic: if close is near the high of the bar, buyers won.
       if close is near the low, sellers won.
       The ratio tells you who controlled the bar.

Vote:
  IF buy_pct > 60% → BULL (+1)   // buyers dominated this bar
  IF buy_pct < 40% → BEAR (+1)   // sellers dominated this bar
  IF 40-60%        → abstain      // balanced, no edge

Example: MCL bar high=69.30, low=68.80, close=69.20, volume=15000
  buy_vol = 15000 * (69.20 - 68.80) / (69.30 - 68.80) = 15000 * 0.80 = 12,000
  sell_vol = 15000 * (69.30 - 69.20) / (69.30 - 68.80) = 15000 * 0.20 = 3,000
  buy_pct = 12,000 / 15,000 * 100 = 80% → BULL vote

Why this matters: Price can move on low volume (noise) or high volume (conviction). Volume Stack tells you which side had conviction. An upward move with 80% buy volume is real. An upward move with 45% buy volume is suspect.

Voter 4: EMA Ribbon (8/21/34)

EMA8  = EWM(close, span=8)   // fast (reacts to ~8 bars)
EMA21 = EWM(close, span=21)  // medium
EMA34 = EWM(close, span=34)  // slow (reacts to ~34 bars)

Vote:
  IF EMA8 > EMA21 > EMA34 → BULL (+1)  // all three stacked bullish
  IF EMA8 < EMA21 < EMA34 → BEAR (+1)  // all three stacked bearish
  ELSE → abstain                          // tangled = no clear trend

Example: EMA8=69.15, EMA21=68.90, EMA34=68.70
  69.15 > 68.90 > 68.70 → stacked bullish → BULL vote

Why three EMAs, not one? A single MA gives one data point. Three stacked in order means short, medium, and long-term momentum ALL agree. When they tangle (cross each other), it's a sign the trend is breaking down.

The Bias Tally

// Count votes
bull_count = (KAMA==bull) + (STC==bull) + (VolStack==bull) + (EMA==bull)
bear_count = (KAMA==bear) + (STC==bear) + (VolStack==bear) + (EMA==bear)

IF bull_count ≥ 4 → STRONG_BULL // unanimous
ELIF bull_count ≥ 3 OR (bull_count == 2 AND ema == "bullish")
  → LEAN_BULL // majority, or 2+trend confirmation
ELIF bear_count ≥ 4 → STRONG_BEAR
ELIF bear_count ≥ 3 OR (bear_count == 2 AND ema == "bearish")
  → LEAN_BEAR
ELSE → NEUTRAL // no agreement → NO TRADE

Why the EMA tiebreaker? When only 2 of 4 voters agree on direction, we need a tiebreaker. The EMA ribbon gets that role because trend structure is the most reliable edge in futures markets. If 2 voters say bull and the trend is bullish, that's enough conviction. If 2 voters say bull but the trend is bearish, the disagreement is too large — we sit out.

NEUTRAL = NO TRADE. Period. If the four voters can't agree on a direction, the edge is gone and we sit on our hands. This is the single most important filter in the system — it prevents trading in chop, which is where most retail accounts die.
Layer 4 — Entry Timing

When exactly do we pull the trigger?

Layer 4 combines Layers 1-3 with the STC crossover and IB breakout to determine the exact entry moment.

// Priority 1: Regime veto
IF regime == EXHAUSTED AND consumed > 90% AND |phase| > 61.8
  THEN FADE_EXTREME // counter-trend fade only
IF regime == EXHAUSTED (other) THEN NO_TRADE

// Priority 2: Bias veto
IF bias == NEUTRAL THEN NO_TRADE

// Priority 3: Structure-boosted entry (no STC crossover needed)
IF structure == BUYER_CONTROL AND bias is bullish AND regime == TRENDING_BULL
  THEN ENTRY_NOW // highest conviction long
IF structure == SELLER_CONTROL AND bias is bearish AND regime == TRENDING_BEAR
  THEN ENTRY_NOW // highest conviction short

// Priority 4: IB breakout (fresh breakout this bar)
IF close > IB_HIGH AND prev_close ≤ IB_HIGH AND bias is bullish
  THEN ENTRY_NOW // IB breakout long
IF close < IB_LOW AND structure == SELLER_CONTROL AND bias is bearish
  THEN ENTRY_NOW // IB breakdown short

// Priority 5: Standard STC crossover
IF bias is bullish AND STC crosses above OS threshold
  THEN ENTRY_NOW
IF bias is bearish AND STC crosses below OB threshold
  THEN ENTRY_NOW

// Priority 6: STC in no-man's-land
IF 20 ≤ STC ≤ 80 THEN WAIT_FOR_PULLBACK
ELSE NO_TRADE

Entry Signal Taxonomy

There are four distinct entry types, ranked by conviction:

Type A: Structure-Confirmed Trend Entry HIGHEST CONVICTION

Conditions: All three required simultaneously:

1. Structure = BUYER_CONTROL (or SELLER_CONTROL for shorts)
2. Bias = STRONG_BULL or LEAN_BULL (or bearish equivalent)
3. Regime = TRENDING_BULL (or TRENDING_BEAR)

Why it works: Price has accepted above the value area AND above the prior session's Initial Balance. Three independent confirmation systems agree. This is the "the building is on fire, run with the crowd" setup. No STC crossover required — the structural evidence is overwhelming.

Position size: Full allocation (1% risk budget).

Type B: IB Breakout Entry HIGH CONVICTION

Conditions:

1. Close crossed above IB High this bar (was below on prior bar) + bullish bias
2. OR: Close below IB Low + SELLER_CONTROL structure + bearish bias

Why it works: The Initial Balance (first 60 minutes of regular trading hours) establishes the "playground" for the session. A breakout from this range with directional confirmation is a powerful intraday signal. Extensions target 50%, 100%, and 3x the IB range.

Position size: Full allocation.

Type C: STC Crossover Entry STANDARD

Conditions:

1. Bullish bias + STC crosses above OS threshold (15 for MNQ/MCL)
2. OR: Bearish bias + STC crosses below OB threshold (92 MNQ / 83 MCL)

Why it works: The Schaff Trend Cycle is a double-smoothed MACD/stochastic hybrid that catches momentum inflection points. Crossing out of oversold/overbought territory signals a regime shift in momentum. Combined with directional bias confirmation, this is the "bread and butter" signal.

Position size: Full allocation.

Type D: Fade Extreme COUNTER-TREND

Conditions:

1. Regime = EXHAUSTED (ATR consumed > 90%)
2. Phase Oscillator at extreme (> 61.8 or < -61.8)

Why it works: When a market has consumed > 90% of its expected range AND the phase oscillator is at a Fibonacci extreme, mean reversion is statistically likely. This is the "rubber band" trade — aggressive, counter-trend, confirmed by Keltner 3x channel extremes.

Position size: Half allocation (0.5% risk). Counter-trend = conservative sizing.

Kelly Criterion (Quarter-Kelly, Advisory Only)

Once we have 30+ trades of live data, the system computes the Kelly fraction: f* = (bp - q) / b where b = avg_win/avg_loss, p = win_rate, q = 1-p. Capped at 0.25 (quarter-Kelly) for safety. This provides a theoretical optimal risk fraction that we compare against the ATR-based calculation — we always use the more conservative of the two.

Complete Indicator Formula Reference

Every indicator used by JARVIS, from raw OHLCV to final value. Source: engine/backtest/indicators.py and engine/backtest/signals.py. All implementations are pure Python/NumPy — no TA-Lib dependency.

1. Wilder's Average True Range (ATR)

Used by: Regime (range consumed), Phase Oscillator, Stop/Target levels, Keltner Channels, Position Sizing

Source: Saty ATR Levels ThinkScript

True Range (TR):
  TR[i] = max(
    high[i] - low[i],              // today's range
    |high[i] - close[i-1]|,       // gap up + today's range
    |low[i] - close[i-1]|         // gap down + today's range
  )

Wilder's ATR (period=14):
  ATR[13] = mean(TR[0], TR[1], ..., TR[13])     // seed: simple average of first 14 TRs
  ATR[i]  = (ATR[i-1] * 13 + TR[i]) / 14        // Wilder smoothing (recursive)

Key property: Wilder smoothing is slower than EMA — it "remembers" more history.
This prevents ATR from spiking on a single volatile bar.

Used in Layer 5 (position sizing):
  risk_per_contract = ATR * contract_multiplier
  contracts = (equity * risk_pct) / risk_per_contract

2. Schaff Trend Cycle (STC)

Used by: Layer 3 (Bias vote), Layer 4 (Entry crossover trigger)

Source: shared_OB_STYLE_CYCLE ThinkScript — the primary entry timing indicator

Step 1: MACD Line
  EMA_fast = EWM(close, span=23)
  EMA_slow = EWM(close, span=50)
  MACD = EMA_fast - EMA_slow

Step 2: First Stochastic of MACD (K-period=10)
  K1[i] = (MACD[i] - min(MACD, 10 bars)) / (max(MACD, 10 bars) - min(MACD, 10 bars)) * 100
  D1 = EWM(K1, span=3)    // smooth with 3-period EMA

Step 3: Second Stochastic of D1 (K-period=10)
  K2[i] = (D1[i] - min(D1, 10 bars)) / (max(D1, 10 bars) - min(D1, 10 bars)) * 100
  STC = EWM(K2, span=3)   // smooth again
  STC = clamp(STC, 0, 100)

Result: oscillator 0-100 that spends most time at extremes.
  STC near 0 → oversold (momentum exhausted to downside)
  STC near 100 → overbought (momentum exhausted to upside)

Entry crossover signals:
  stc_cross_up   = STC[i] > OS_threshold AND STC[i-1] <= OS_threshold
  stc_cross_down = STC[i] < OB_threshold AND STC[i-1] >= OB_threshold

Per-instrument thresholds:
  MCL: OS=15, OB=83  (standard — crude trends cleanly)
  MNQ: OS=15, OB=92  (higher OB filters Nasdaq noise — fewer false overbought signals)
  MES: OS=15, OB=83  (standard, used in composite with ORB+VWAP)

3. KAMA — Kaufman Adaptive Moving Average

Used by: Layer 3 (Bias vote)

Source: NextSignalMomentum ThinkScript

Parameters: period=10, fast_period=2, slow_period=30

Step 1: Efficiency Ratio (ER)
  change = |close[i] - close[i - 10]|         // net price change over 10 bars
  volatility = sum(|close[j] - close[j-1]|, j=i-9..i)  // total bar-to-bar movement
  ER = change / volatility                     // 0 to 1.0

  ER = 1.0 → price moved in a straight line (perfect trend)
  ER = 0.0 → price went nowhere despite lots of movement (pure chop)

Step 2: Smoothing Constant (SC)
  fast_sc = 2 / (2 + 1) = 0.6667
  slow_sc = 2 / (30 + 1) = 0.0645
  SC = (ER * (fast_sc - slow_sc) + slow_sc)^2

  When ER=1.0: SC = (0.6667)^2 = 0.444  → very responsive
  When ER=0.0: SC = (0.0645)^2 = 0.004  → nearly frozen

Step 3: KAMA Update
  KAMA[i] = KAMA[i-1] + SC * (close[i] - KAMA[i-1])

Key insight: SC is SQUARED, making the adaptation non-linear.
In chop (ER≈0), KAMA barely moves (avoids whipsaws).
In trend (ER≈1), KAMA tracks price closely (captures moves).

4. Phase Oscillator

Used by: Layer 1 (Regime classification, compression detection)

Source: Saty Phase Oscillator ThinkScript

Phase Value:
  EMA21 = EWM(close, span=21)
  ATR14 = Wilder_ATR(high, low, close, period=14)
  Phase = (close - EMA21) / (3 * ATR14) * 100
  Phase = clamp(Phase, -100, +100)

  Division by 3*ATR normalizes the deviation to a "3 ATR band" — a standard
  statistical measure of how extreme price is vs its moving average.

Fibonacci interpretation zones:
  Phase > +61.8  → extended up (exhaustion zone)
  Phase +23.6 to +61.8 → bullish
  Phase -23.6 to +23.6 → neutral
  Phase -61.8 to -23.6 → bearish
  Phase < -61.8  → extended down (exhaustion zone)

Compression Detection:
  BB_width = 4 * rolling_stddev(close, 21)    // Bollinger Band width
  ATR_width = 2 * ATR14                        // ATR channel width
  is_compression = (BB_width < ATR_width)

  When realized volatility (stddev) < expected volatility (ATR):
    → market is "coiling" — energy building for a directional move
    → direction is unknown → do not enter

5. Volume Stack

Used by: Layer 3 (Bias vote)

Source: Saty Volume Stack ThinkScript

Estimating buy vs sell volume from a single OHLCV bar:
  buy_volume  = volume * (close - low) / (high - low)
  sell_volume = volume * (high - close) / (high - low)
  buy_pct     = buy_volume / (buy_volume + sell_volume) * 100

Intuition: where did the bar close relative to its range?
  Close at the HIGH → (close-low)/(high-low) = 1.0 → 100% buy volume
  Close at the LOW  → (close-low)/(high-low) = 0.0 → 0% buy volume
  Close at midpoint → 50/50 split

Edge case: high == low (doji bar) → buy_pct defaults to 50%

Thresholds:
  buy_pct > 60% → "buyer_dominant"  (BULL vote)
  buy_pct < 40% → "seller_dominant" (BEAR vote)
  40-60%         → "balanced"       (no vote)

This is a bar-level proxy for order flow. It's not as precise as tick data
or Level 2 DOM, but across many bars the signal is statistically significant.

6. EMA Ribbon (8/21/34)

Used by: Layer 1 (Regime trend input), Layer 3 (Bias vote + tiebreaker)

Source: Saty ATR Levels ThinkScript

EMA (Exponential Moving Average):
  EMA[0] = close[0]  (seed)
  EMA[i] = close[i] * alpha + EMA[i-1] * (1 - alpha)
  where alpha = 2 / (span + 1)

Three spans:
  EMA8:  alpha = 2/9  = 0.222  (fast — reacts to ~8 bars of history)
  EMA21: alpha = 2/22 = 0.091  (medium)
  EMA34: alpha = 2/35 = 0.057  (slow — reacts to ~34 bars of history)

Trend classification:
  EMA8 > EMA21 > EMA34 → "bullish" (all three aligned up — stacked)
  EMA8 < EMA21 < EMA34 → "bearish" (all three aligned down — stacked)
  Any other order       → "neutral" (crossed/tangled — no clear trend)

Why stacking matters: when a fast EMA crosses a slow EMA, it's a "golden cross"
or "death cross." When ALL THREE are stacked, it means short, medium, AND
long-term momentum agree. This is a strong filter for choppy markets.

7. Keltner Channels (1.5x / 2.0x / 3.0x)

Used by: Exhaustion/reversal detection, OB Omega confirmation

Source: KMaster / OB_OMEGA ThinkScript

Basis = SMA(close, 20)
ATR = SMA of True Range (NOT Wilder's — uses simple MA of TR over 20 bars)

Inner Channel (1.5x):
  Upper = Basis + 1.5 * ATR
  Lower = Basis - 1.5 * ATR

Outer Channel (2.0x):
  Upper = Basis + 2.0 * ATR
  Lower = Basis - 2.0 * ATR

Extreme Channel (3.0x):
  Upper = Basis + 3.0 * ATR
  Lower = Basis - 3.0 * ATR

Interpretation:
  Price at 1.5x band → normal trending move
  Price at 2.0x band → extended move, potential pullback
  Price at 3.0x band → extreme extension, high probability of reversal
    → This is where FADE_EXTREME entries trigger (combined with Phase > 61.8)

8. CCI — Commodity Channel Index (period=50)

Used by: Available for analysis, not currently a direct bias voter

Source: shared_mtftrendbar ThinkScript

Typical Price (TP) = (high + low + close) / 3
MA = SMA(TP, 50)
Mean Deviation = mean(|TP[i] - MA|, last 50 bars)
CCI = (TP - MA) / (0.015 * Mean_Deviation)

The 0.015 constant normalizes so ~75% of values fall between -100 and +100.
  CCI > 0: price above its average → bullish pressure
  CCI > +100: strongly above average
  CCI < -100: strongly below average
  Zero-cross: trend direction change

9. Range Consumed %

Used by: Layer 1 (Regime — primary exhaustion detector)

range_consumed = |close - prior_close| / ATR * 100

Capped at 200% (2x ATR move — extremely rare, gap day).

  consumed < 50%  → low range used, room for expansion
  consumed 50-70% → moderate, still room to run
  consumed > 70%  → getting stretched
  consumed > 90%  → EXHAUSTED — most of the expected move is done

This is the simplest but most important filter in the regime layer.
It answers: "how much of today's expected range has already been used?"

10. VPOC / VAH / VAL Approximation

Used by: Layer 2 (Structure Map)

VPOC (Volume Point of Control):
  VPOC = rolling_sum(close * volume, 20) / rolling_sum(volume, 20)
  This is a 20-bar VWAP — the volume-weighted average price.
  It approximates where the most volume transacted.

VAH (Value Area High):
  VAH = rolling_quantile(high, 20, 0.85)
  The 85th percentile of the last 20 bars' highs.

VAL (Value Area Low):
  VAL = rolling_quantile(low, 20, 0.15)
  The 15th percentile of the last 20 bars' lows.

The spread [VAL, VAH] captures roughly 70% of price action.
This mirrors the TPO Value Area concept but works from OHLCV bars
without tick-level data.

These are the "value" reference points that Layer 2 uses to determine
whether price is inside value (neutral) or has been accepted outside
value (buyer/seller control).

11. Initial Balance (IB) Levels

Used by: Layer 2 (Structure), Layer 4 (IB breakout entry)

Live Intraday Calculation (minute bars):
  IB_HIGH = max(high[bar]) for bars from 9:30 to 10:30 AM ET
  IB_LOW  = min(low[bar]) for bars from 9:30 to 10:30 AM ET
  IB_RANGE = IB_HIGH - IB_LOW

Hourly Backtester Approximation:
  IB_HIGH = high[i-1]     // prior bar's high
  IB_LOW  = low[i-1]      // prior bar's low

Extension Targets (from IB_RANGE):
  Quartiles (within IB):
    Q25 = IB_LOW + 0.25 * IB_RANGE
    Q50 = IB_LOW + 0.50 * IB_RANGE  (midpoint)
    Q75 = IB_LOW + 0.75 * IB_RANGE

  Extensions (beyond IB):
    50% up    = IB_HIGH + 0.50 * IB_RANGE
    100% up   = IB_HIGH + 1.00 * IB_RANGE
    300% up   = IB_HIGH + 3.00 * IB_RANGE
    (mirror for downside)

IB Breakout Detection:
  Long:  close[i] > IB_HIGH AND close[i-1] <= IB_HIGH  (fresh breakout this bar)
  Short: close[i] < IB_LOW  AND structure == SELLER_CONTROL

12. Position Size Formula

Used by: Layer 5 (SafetyLayer + position_sizer)

ATR-Based Risk Budget:
  risk_budget = equity * effective_risk_pct / 100
  risk_per_contract = ATR * contract_multiplier
  contracts_raw = floor(risk_budget / risk_per_contract)

Drawdown Scaling:
  IF drawdown < 5%   → scale = 1.00
  IF drawdown 5-8%   → scale = 0.75
  IF drawdown 8-10%  → scale = 0.50
  IF drawdown > 10%  → scale = 0.00 (HALT)
  effective_risk_pct = risk_pct * scale

Hard Limits Applied:
  contracts = min(contracts_raw, MAX_CONTRACTS_PER_INSTRUMENT)
  position_value = contracts * ATR * multiplier
  IF position_value > equity * MAX_POSITION_SIZE_PCT → reduce contracts

Consecutive Loss Adjustment:
  IF consecutive_losses >= 3 → contracts *= 0.50
  IF consecutive_losses >= 5 → contracts *= 0.25
  IF consecutive_losses >= 7 → contracts = 0 (24-hour halt)

Kelly Criterion (advisory, post-30-trade):
  f* = (b*p - q) / b
  where b = avg_win/avg_loss, p = win_rate, q = 1-p
  Capped at 0.25 (quarter-Kelly) for safety
  Used as sanity check against ATR-based sizing, take the lower

13. Composite Score (MES Only)

Used by: MES composite signal generator (STC + ORB + VWAP)

Three signal sources, each fires 0 or 1:
  STC_long  = 1 if stc_cross_up this bar, else 0
  ORB_long  = 1 if ORB LONG_ENTRY, else 0
  VWAP_long = 1 if VWAP LONG_ENTRY, else 0
  (mirror for short)

Regime-Adaptive Weights:
  TRENDING: w_stc=0.60, w_orb=0.30, w_vwap=0.10  (STC dominates)
  RANGING:  w_stc=0.50, w_orb=0.20, w_vwap=0.30  (VWAP gets more weight)
  VOLATILE: w_stc=0.00, w_orb=0.00, w_vwap=0.00  (sit out entirely)

Composite Score:
  long_score  = w_stc * STC_long + w_orb * ORB_long + w_vwap * VWAP_long
  short_score = w_stc * STC_short + w_orb * ORB_short + w_vwap * VWAP_short
  composite   = long_score - short_score  (positive = bullish, negative = bearish)

Entry Gate:
  ENTRY_NOW requires:
    1. score >= 0.35 (entry threshold)
    2. STC must fire (STC is the GATE — ORB/VWAP add score but can't enter alone)
    3. regime != VOLATILE
    4. R:R >= 1.2 (reward/risk at T1)

  Why 0.35? STC alone in TRENDING regime = 0.60 (passes). STC alone in RANGING = 0.50 (passes).
  VWAP alone in RANGING = 0.30 (blocked). This prevents VWAP-only entries which have lower edge.

14. Stop / Target Calculations

For LONG entries:
  stop_level = close - STOP_ATR * ATR      // below entry
  target_1   = close + T1_ATR * ATR        // first profit target
  target_2   = close + T2_ATR * ATR        // stretch target
  target_3   = close + T3_ATR * ATR        // full extension

For SHORT entries:
  stop_level = close + STOP_ATR * ATR      // above entry
  target_1   = close - T1_ATR * ATR
  target_2   = close - T2_ATR * ATR
  target_3   = close - T3_ATR * ATR

Per-Instrument ATR Multiples:
  MCL: STOP=0.90, T1=1.50, T2=2.618, T3=4.00   R:R at T1 = 1.67:1
  MNQ: STOP=0.70, T1=1.00, T2=1.80,  T3=2.618  R:R at T1 = 1.43:1
  MES: STOP=1.00, T1=2.50, T2=4.00   (composite) R:R at T1 = 2.50:1

Breakeven WR (to be profitable at T1 only, ignoring T2/T3):
  MCL: 1 / (1 + 1.67) = 37.5%  (need to win 37.5% of trades to break even)
  MNQ: 1 / (1 + 1.43) = 41.2%
  MES: 1 / (1 + 2.50) = 28.6%

  With tiered exit (50% at T1, 25% at T2, 25% at T3), effective R:R improves
  significantly — a winning trade that hits all three targets returns much
  more than the nominal T1 R:R.
