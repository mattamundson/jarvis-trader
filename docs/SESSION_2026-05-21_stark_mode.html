The complete autonomous loop

End-to-end, hands-off after activation. You can override any step.

1
Autonomous tick fires every 10 minutesEngine background task runs against active symbols (MCL, MNQ). Skips tick if kill switch active, live trading enabled, or engine unhealthy.
2
Pipeline runs the 5-stage analysisnews_analyst → social_analyst → pattern_vision_analyst → kronos_classifier (off) → options_analyst (stage 6, off) → advisor → trader. Gate v2 thresholds + safety layer evaluated.
3
Verdict gated by confidence ≥ 0.75 AND fund manager greenConservative bar. If skipped, tick ends silently. If green: candidate row inserted into pipeline_approval_queue with 30-minute TTL + idempotency key.
4
Discord webhook fires fire-and-forgetPosts rich embed to channel 1490851279180660819: symbol, direction, entry/stop/target, confidence, expiry, Hermes skill hint. Webhook failure never blocks the queue.
5
You react from anywhere✅ approve · ❌ reject · ⏸ extend TTL. Discord gateway delivers the event to the reaction watcher.
6
Reaction watcher validates + routesChecks: message is bot's own + reactor user_id matches DISCORD_PERSONAL_USER_ID. Calls POST /approvals/{id}/{approve|reject|extend} with X-API-Key.
7
Approval submits IB bracket orderParent (entry) + stop (LMT/STP child) + target (LMT child) submitted atomically. ocaGroup linking — one cancels the other. Broker-side risk management, not just safety-layer monitoring.
8
Result posts back to Discord✅ Approved (order INV-12345) · ❌ Rejected: reason · ⏰ Expired (TTL). Trading journal auto-generates daily 5pm CT summary to vault.

The strategy that produced the May 9 peak needs investigation. Risk attribution endpoint /attribution/daily?date=2026-05-09 can decompose what drove the peak.

Known risks — explicit, mitigated for paper, gating for live

RISK 1 — IB paper bracket race

IB paper account sometimes fills MKT parent orders instantly; the STP child can race the fill. Existing submit_entry_with_stop in safety_layer.py has the same race. Mitigated in paper mode (worst case: orphaned child order, logged). Phase 3 prerequisite: add _verify_parent_linkage() post-submission check.

RISK 2 — Reaction-as-auth security

If your Discord account is compromised, an attacker with access to channel 1490851279180660819 can ✅-react to bot-posted approval messages. Mitigated today by paper-only mode (worst case: logged paper order). Phase 3 prerequisite: add signed HMAC token to bot-posted messages that the watcher verifies before approving.

RISK 3 — Pro-rata risk attribution double-counts correlated signals

When two structurally correlated analysts (e.g. technical + regime_adjust from STC) both signal bullish on the same trade, each receives half the credit for what's effectively one underlying signal. Attribution is accurate as a proportional audit trail but should not be read as a causal scorecard. Documented in RISK_ATTRIBUTION_RUNBOOK.md; SHAP-style attribution is the future-work path.
