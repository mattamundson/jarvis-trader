Architecture & Engine

The three-tier stack

JARVIS TRADER is a FastAPI-based trading engine running on port 8010, fronted by a Next.js dashboard on port 3010. The engine orchestrates a 5-stage multi-agent LLM pipeline, a rule-based safety layer, and live broker connectivity to IB Gateway. All three tiers run on the same Windows 11 host.

Tier 1 — Dashboard

3010
Next.js App Router · pnpm · SWR polling · shadcn/ui

Tier 2 — Engine API

8010
FastAPI · uvicorn · 63 routers · 230+ endpoints · SQLite

Tier 3 — Brokers + Data

4002
IB Gateway paper · Polygon · TV CDP 9222 · Schwab (Phase 3)

Before a strategy verdict can be marked APPROVED (and live paper orders enabled), all 4 thresholds must pass on a fresh walk-forward-engine (WFE) run.

pf_ci_lower ≥ 1.10 Profit factor 95% confidence interval lower bound; min 1.10 = 10% edge

dsr ≥ 0.10 Deflated Sharpe ratio (accounting for overfitting); min 0.10 credibility

Backtest Suite

Full Backtest (backtester.py)

End-to-end historical replay (2022–2026) with OHLCV bar data, slippage modeling, and commission. Runs on single signal per symbol. Output: Sharpe, Sortino, PF, max DD, trade diary. Used for initial hypothesis validation and sensitivity analysis.

Walk-Forward Engine — WFE (walk_forward.py, rolling_wfe_scheduler.py)

Weekly rolling out-of-sample validation: train 60d, test 20d, roll forward 1 week. Produces PF / Sharpe / DD on held-out future data. WFE score is the aggregate out-of-sample PF CI lower bound. This is the primary verdict metric (gate v2 requires WFE ≥ 0.6 for approval).

Stark Forge (stark_forge.py)

Brute-force parameter grid search over canonical signal space (STC fast/slow, breakout thresholds, regime tiers). Leverages Bayesian optimization to reduce search space. Output: ranked list of (params, out-of-sample PF). Used to discover new signal flavors and rank variants.

Monte Carlo Simulation (monte_carlo.py)

Resamples trade sequence and P&L distribution 10K times to estimate tail risk (95th percentile drawdown, VaR). Gate v2 gates on mc_95th_dd ≤ 5%. Accounts for serial dependence via block-bootstrap resampling.

Order types

  • Single market order (MKT) — legacy path; still used when ENABLE_BRACKET_ORDERS=0.
  • Limit order (LMT) — supported as parent action type in bracket constructor when order_type="LMT" is passed.
  • Bracket (parent MKT + STP child + LMT take-profit) — shipped 2026-05-21. Three-leg atomic submission: entry uses transmit=False, STP child uses transmit=False, TP child uses transmit=True to trigger the atomic batch. STP and TP share an OCA group (JARVIS_BRACKET_<ACTION>_<price>) so whichever fills first cancels the other. Rollback on STP failure: cancel_order(entry) attempted and logged at CRITICAL if rollback also fails.

Bracket orders are enabled by default (ENABLE_BRACKET_ORDERS=1) and read the flag fresh on each approval — no engine restart required to toggle.

Bracket orders are paper-mode only

submit_bracket() hard-checks settings.LIVE_TRADING_ENABLED and aborts with approved=False if it is ever True. This is a second safety layer on top of the port block.

IB Scanner

Read-only market scanner using reqScannerData. Default OFF (ENABLE_IB_SCANNER=0). Uses a dedicated client ID 10 to avoid interfering with trading connections. Connects to paper port 4002 as a separate short-lived session per scan request. Supported scan codes include TOP_PERC_GAIN, TOP_PERC_LOSE, HOT_BY_VOLUME, FUT_HOT_BY_VOLUME, and 7 others. IB caches scanner results server-side for up to 30 seconds — re-call at 60s intervals for fresh data.

Real-time data from IB

  • Historical bars: reqHistoricalDataAsync — 5-min, 1-hour, 1-day intervals. Used for backfill and as snapshot fallback.
  • L1 snapshot: reqTickersAsync — last/close/bid/ask. Falls back to last historical bar close on IB Error 354 (not subscribed).
  • Real-time 5-second bars: reqRealTimeBars with callback push.
  • Account / positions: injected via IBGatewayManager connection.

Throttling and reconnect

Chunked historical fetch: --chunk-days 5 workaround for Gateway crash on large date-range requests (implemented 2026-05-07 for MES R11 + MGC R4 backfills).

Forbidden / blocked surfaces

Live IB Gateway port 4001 — permanently blocked

LIVE_TRADING_PORTS = frozenset({4001, 7496}) is checked in three places: IBGatewayConfig.__post_init__, IBGatewayManager.__init__, and IBGatewayManager.connect(). Any attempt to construct an IB connection on these ports raises ValueError before the TCP socket is opened. The port block is not configurable via env — it requires a code change guarded by a [safety-review] PR tag.

Bracket orders blocked in live mode

submit_bracket() checks settings.LIVE_TRADING_ENABLED at runtime and returns approved=False with a CRITICAL log entry if it is True. This is a redundant safety layer — the port block should prevent live orders from reaching the broker, but the bracket module adds its own assertion in case the safety layer is ever misconfigured.

Polygon futures blocklist — never query futures via Polygon WebSocket

POLYGON_FUTURES_BLOCKLIST covers MCL, MNQ, MES, MGC, M2K, MYM, CL, NQ, ES, GC, RTY, YM, SI, ZB, ZN. Callers must check this set before subscribing. Violating it returns consumer-goods or random equity stock prices — which the 2026-04-16 audit confirmed backfilled into strategy metrics without detection for days.

Hermes gateway — never restart from a debug session

Restarting the Hermes messaging gateway drops Discord messages for 10–73 seconds. Always use hermes-safe-restart.sh (coordinated restart helper). Never issue a raw pm2 restart or systemctl restart to the Hermes service from inside a JARVIS debug or analysis session.
