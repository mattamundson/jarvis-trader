Finding 2: No CLAUDE.md

Critical The single most important file for Claude Code projects is missing

The everything-claude-code repo emphasizes CLAUDE.md as the project-level configuration that tells Claude how to work with this codebase. JARVIS TRADER has no CLAUDE.md at all. This means every new session starts cold — Claude has to re-discover the architecture, conventions, safety rules, and patterns from scratch (or rely on memory files, which are less structured).

What CLAUDE.md should contain for JARVIS TRADER

Project description, tech stack, architecture overview (5-stage pipeline, 10 agents), critical safety rules (never use LLM for safety decisions), testing commands, key file locations, coding conventions, environment setup, and a pointer to the docs/ directory for detailed references.

Finding 5: No Rules or Hooks Infrastructure

Medium Missing the ECC rules/, hooks/, and contexts/ pattern

The everything-claude-code approach uses:

rules/ — Always-follow coding guidelines (coding-style.md, git-workflow.md, testing.md, security.md) that Claude loads automatically. JARVIS TRADER has no equivalent — conventions are scattered across memory files and README.

hooks/ — Automated triggers (pre-commit secret detection, post-edit type checking, session start/end state persistence). The project has scripts/check-secrets.sh but it's not wired as a proper Claude Code hook.

contexts/ — Dynamic prompt injection for different modes (dev, review, trading). Would be valuable for JARVIS TRADER to have a "trading-review" context vs. "development" context.

Finding 6: Engine Internal Structure is Good

Good Engine module organization follows clean architecture

The engine's internal structure is solid: agents/, backtest/, cache/, database/, execution/, llm/, middleware/, monitoring/, risk/, websocket/, api/, tests/. This follows the domain-driven pattern well. No changes needed here.

Finding 7: No .claude/ Project Configuration

High .claude/ directory has only settings.local.json — missing agents/, rules/, project config

Per ECC patterns, .claude/ should contain project-specific agent definitions, rule overrides, and configuration. Currently it only has one settings file. The GMS Intelligence skills live in a remote plugin path, but there's no local .claude/agents/ defining the JARVIS-specific agent behaviors (technical analyst persona, risk manager rules, etc.).

Finding 8: Scripts Directory Needs Organization

Medium scripts/ mixes operational scripts, analysis scripts, and documentation

The scripts directory contains bash operational tools (health_check.sh, start_paper_trading.sh), Python analysis tools (seed_paper_trades.py, smoke_test.py), a TradingView Pine script, and a markdown setup guide — all flat in one directory.
