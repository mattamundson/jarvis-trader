## 6. Key Decisions Made This Session

### Decision 1: Server-Side Stop Correction (Not LLM Retry)
When the stop direction bug was discovered, the choice was between:
- Option A: Add stronger wording to the LLM prompt ("you MUST use long_stop for buy, NEVER short_stop")
- Option B: Add server-side validation that corrects the stop using the known ATR values

**Chose Option B.** The LLM already has clear instructions (`INSTRUCTION: If action=buy, use long_stop as stop_price`). Prompt-only fixes are unreliable for intermittent LLM compliance issues. Server-side correction is deterministic and auditable (adds a warning log). The ATR values needed for correction are already computed in the same method.

### Decision 2: Preserve All Open Trades in `get_portfolio()` (Not Deduplicate)
The original `by_symbol` design was suited for live trading (1 position per symbol enforced by broker). In paper trading mode, multiple open positions per symbol are valid and intentional (accumulating MCL shorts over time). Changed to preserve all entries.

**Side effect**: The `positions` list passed to risk/fund managers will now contain individual trade-level records (not symbol-level aggregates). The risk manager's correlation check iterates over this list looking for `symbol`, `quantity`, `unrealized_pnl`, and `sector`. The `unrealized_pnl` will still show `$0.00` (no live price feed), and `sector` will still show `unknown`. These are informational gaps but don't block approvals.

### Decision 3: `.gitignore` Uses Unquoted Path for Space-Containing Directory
Initial attempt used `"Markdown FIles/"` with double quotes — but `.gitignore` does not interpret quotes as shell quoting. Fixed to plain `Markdown FIles/`. In `.gitignore`, spaces in paths are literal and require no quoting.

## 7. Corey Auction Analyst — New Agent Architecture (Uncommitted)

This is a major new feature added in a prior session that is currently running in the live engine. Full documentation follows to prevent context loss.

### Purpose
A new Stage 1 parallel analyst that adds **Corey's TPO/auction theory commentary** to the pipeline's signal stack. Corey is a professional futures trader who posts daily commentary in the JARVIS Discord server. The agent extracts his session bias (bullish/bearish/neutral), key price levels, session type (range day, trend day, etc.), and Initial Balance context — then cross-references active Discord bot signals for the symbol.

### Data Sources
Both tables exist and have data in `engine/data/jarvis_trader.db`:
- `discord_corey_commentary`: **64,943 rows** — Corey's raw text commentary scraped from Discord channels `market-updates` and `general` (filtered to author ID `564449478174703646` = tathedog)
- `discord_bot_signals`: **215,887 rows** — Discord bot trade signals (direction, entry, target1/2, stop, win_rate, R:R)
- `corey_session_bias`: **1 row** — Daily cache table (LLM extraction results stored here to avoid repeated Haiku calls)

### Signal Computation
```
base_signal = {"bullish": +0.5, "bearish": -0.5, "neutral": 0.0}[directional_bias]
bot_boost   = ±0.3 (within 1.5× ATR) | ±0.5 (within 0.5× ATR) | 0 if no signal
signal      = clamp(base_signal + bot_boost, -1.0, +1.0)

win_rate_multiplier = 0.7 + 0.6 × ((win_rate − 0.5) / 0.5)   # 0.7 at 50%, 1.3 at 100%
confidence  = min(1.0, commentary.conviction × win_rate_multiplier)
              capped at 0.4 if data_quality == "stale"
```

### Symbol Mapping
`MES→ES, MNQ→NQ, MCL→CL, MGC→GC, MYM→YM, M2K→RTY`

### LLM Model
Claude Haiku (`claude-haiku-4-5-20251001`) — fast and cheap for daily commentary extraction. Results cached in `corey_session_bias` table. Cache hit = no LLM call.

### Graceful Degradation
- No commentary data → `signal=0.0, confidence=0.0, data_quality="none"` (neutral, no pipeline impact)
- No bot signals → `bot_boost=0.0` (commentary-only signal)
- No API key → neutral report, no LLM call
- Any exception in analysis → `_neutral_report()` returned, pipeline continues normally

### Current Wiring Issue
The pipeline call in `pipeline.py` passes `current_price=0.0, atr=0.0`. This means:
- Bot proximity boost is disabled (distance from entry cannot be computed without current price)
- `bot_boost` will be a fixed `±0.3` (signal exists, no price data → moderate boost)
- To enable proximity boost: pass real `current_price` and `atr` from the technical analyst report
