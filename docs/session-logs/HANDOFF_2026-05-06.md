### Phase B — Engine Restart (OLLAMA_NUM_CTX_PER_AGENT Activation)

Engine was restarted to activate the new env knob. The restart encountered a port-race condition: `restart_engine.ps1` killed the old uvicorn process but pm2 immediately relaunched it before the script's `Start-Process` attempt. The script exited with code 1 (health poll timed out during churn), but pm2 self-healed and the engine came up healthy on its own.

**Root cause of the false exit discovered during this phase:** `restart_engine.ps1` health poll used `localhost:8010`. Fixed in `8b0a951` (both health poll locations on lines 41 and 234).

Audit of the paper trading pipeline discovered **three independent gaps** that prevented MES from ever generating paper trades, despite being listed as "running." This was a silent failure — no errors, just no trades.

```python
    "strategy": "sma_trend",
    "params": {"fast": 50, "slow": 200, "atr_trail_mult": 2.0},
    "capital": 50_000.0,

    "interval": "1h"

```
And added MES to `ACTIVE_INSTRUMENTS = ['MCL', 'MNQ', 'MES']`.

**Gap 2 — paper_runner.py calling wrong signal function:**  
`engine/routers/paper_runner.py` was routing all instruments through `generate_signals()` (the STC/breakout path). The SMA trend strategy uses `generate_instrument_signals()`. The call was not branched on strategy type.  
Fix: Added conditional dispatch:
```python
if cfg.get("strategy") == "sma_trend":
    signals = generate_instrument_signals(symbol, df, cfg["params"])
else:
    signals = generate_signals(symbol, df, cfg["params"])
```

**Gap 3 — MES excluded from APPROVED_PAPER_SYMBOLS:**  
`engine/validation/validation_gate_config.py` listed `APPROVED_PAPER_SYMBOLS` as `{'MCL', 'MNQ'}`. MES signals were validated against the gate and rejected before reaching the paper trade logger.  
Fix: Added `'MES'` to the set.

All three fixes committed together as `d2f5eac`. Without all three, MES paper trading does not function even when the gate v2 verdict is PASS. This was a silent multi-point failure with no visible error at any single layer.

**Capital sizing note:** `MES_TREND_PAPER_CONFIG` uses `capital=50_000.0`. This is required by the ALT gate routing — MES trend passed via ALT path which is restricted to $50K+ accounts. The position sizer uses capital as its base; below $50K, micro futures contract sizing may not match the backtest assumptions. ### Phase K — MES Trend RV Filter WFO (This Session's New Work)

After the prior handoff, the identified highest-ROI improvement was running a WFO validation of the realized-volatility regime filter for MES trend.

**Background:** `engine/backtest/trend_signals.py` lines 34–38 document empirical evidence from 36 live champion trades: below RV-20 annualized ≈ 9%, trades net-lose (estimated PF ~0.70); above 9%, PF 2.54 (+23% vs 2.06 baseline). A `min_rv_annualized` parameter already exists in `generate_sma_trend_signals()` but is disabled by default (0.0).

**WFO runner created:** `engine/backtest/run_mes_trend_rv_filter.py` — identical to rank11 in WFO structure (same 18 windows, 6-month IS, 1-month OOS, 3-combo grid), with `MIN_RV_ANNUALIZED=9.0` as the only change.

**Result: FAIL** (committed `2716157`).

Full gate v2 metrics vs rank11 baseline:

| Metric | Threshold | rank11 | rv_filter_rank1 | delta |
|---|---|---|---|---|
| p_edge | ≥ 0.95 | 0.75 | **0.667** | -0.083 |
| fixed_params_min_pf | ≥ 1.20 | 1.3506 | **1.1125** | -0.238 |
| wfo_consistency | MODERATE/STRONG | STRONG | MODERATE | downgrade |
| dsr | ≥ 0.30 (ALT) | 1.000 | 0.754 | -0.246 |
| mc_95th_dd | ≤ 7.0% (ALT) | 0.81% | 0.92% | +0.11% |
| cost_survives_through | ≥ realistic | catastrophic | catastrophic | unchanged |
| OOS windows with trades | (coverage) | 12/18 | 9/18 | -3 windows |
| Total OOS trades | (coverage) | 16 | 12 | -4 trades |

**Root cause of FAIL — the trade frequency problem:**  
The unfiltered SMA strategy generates ~2 entries per 1-month OOS window. With RV≥9% filtering applied, this drops to 0–1 entries per window. 9 of 18 OOS windows had zero trades after filtering. The gate requires `p_edge ≥ 0.95` — 17 of 18 windows must be profitable. When 9 windows are empty (contributing PF=0.0 to the denominator), p_edge cannot mathematically exceed 9/18 = 0.50 even if every single trade that did fire was a winner.

**Per-window comparison reveals additional nuance:**  
The filter actively blocked wins in windows 4 (Jan 2025), 12 (Sep 2025), and 16 (Jan 2026) — each had infinite-PF trades in rank11 that were excluded by the RV filter. In window 8 (May 2025, the worst month), the filter not only failed to block the losing trades but allowed one additional losing trade vs rank11. The filter did not prevent the single worst OOS period.

**Why fixed_params_min_pf degraded:**  
The filter disproportionately hurts the (50,200) champion combo. Unfiltered (50,200) PF=1.3506 (35 trades). Filtered (50,200) PF=1.1125 (21 trades). The removed 14 trades — those entering when RV < 9% — include some legitimate trend entries that happened to fire in moderate-vol regimes. These weren't failing the way the empirical sample implied; the empirical split was not uniform across time.

**Decision:** Production config unchanged. Rank11 (no filter) remains active. The empirical improvement (+23% PF) is not demonstrably false — it may be real — but it cannot be validated via WFO at this trade frequency. The gate is working correctly; it's distinguishing between a genuine OOS-validated edge (rank11) and a full-sample statistical observation that doesn't robustly generalize per-window (filter). See `docs/session-logs/MES_RV_FILTER_ANALYSIS_2026-05-06.md` for the complete deep-dive including per-window table, fixed-params divergence analysis, IS overfit discussion, and path-forward conditions.

### 4a. MNQ — Strategy Family Exhausted, Next Approach Undefined

The MNQ breakout strategy ran 5 parametric sweeps. The final diagnosis: mid-2025 (May–November) represents a structural regime change in NQ behavior — probably a shift from trending to range-bound or increased correlation to macro events (tariff announcements, Liberation Day). This killed all OOS metrics in windows 7–15 and cannot be fixed by parameter selection within the breakout family.

## 5. Key Technical Decisions Made This Session

### 5a. OLLAMA_NUM_CTX_PER_AGENT semantics

Format: `AGENT_NAME=CTX_SIZE` comma-separated (matches `OLLAMA_MODEL_PER_AGENT` pattern). Agent names are exact strings from the agent registry (e.g., `social_analyst`, `news_analyst`). The env var is parsed in `LLMClient.__init__()` and stored as `self.ollama_num_ctx_per_agent: dict[str, int]`. If an agent name is not found in the dict, the global `OLLAMA_NUM_CTX` applies. Current setting:

```
OLLAMA_NUM_CTX_PER_AGENT=social_analyst=2048,news_analyst=2048
```

Prompt size measurements: social_analyst ~430 tokens (1.7x headroom), news_analyst ~1175 tokens worst-case (1.7x headroom at 2048). Confirmed safe.

### 5b. MES paper trading capital = $50K

The MES trend strategy passes gate v2 via the ALT path, which is restricted to `$50K+` accounts. This is not an arbitrary number — the ALT path's `fixed_params_min_pf ≥ 1.20` threshold was calibrated assuming a minimum capital that makes micro futures contract sizing meaningful. Below $50K, position sizing rounds to fewer or zero contracts in some windows, changing the realized PF vs backtest expectations.

If Amo's paper trading capital is tracked at a different amount in the paper broker config, **the $50K in `MES_TREND_PAPER_CONFIG` should still match the backtest assumption**, even if the IB paper account has a different starting balance. The paper runner uses this capital figure only for position sizing calculations, not as an actual account balance.

### 5c. Gate v2 fixed_params_min_pf = floor across all grid combos

The `fixed_params_min_pf` metric runs each grid combo on the full dataset and takes the minimum. This means the worst-performing combo in the grid sets the floor for the entire strategy family. The lesson from rank8–rank11: **never include combos where the fast/slow ratio is outside ±20% of the champion ratio.** Off-axis combos (like fast=50, slow=190 — ratio=0.263 vs champion 0.25) tend to have qualitatively different performance characteristics and drag the floor down.

For future grid designs around SMA strategies:
- Allowed ratio range for champion (50,200)=0.25: [0.20, 0.30]
- (60,200)=0.30: borderline ✅ — empirically passes
- (55,200)=0.275: ✅
- (50,200)=0.25: champion ✅
- (50,190)=0.263: ✅ in theory, but empirically fails
- (50,180)=0.278: untested — might be fine
- Rule of thumb: test any "new" combo against full dataset first; if full-dataset PF < 1.20, exclude from WFO grid

### 5d. MNQ non-stationarity diagnosis

The MNQ breakout FAIL is not parameter sensitivity. The diagnosis is specific: windows 7–15 in the 18-window WFO sequence correspond to May–November 2025. During this period:
- IS-selected params consistently overfit to the preceding period's breakout characteristics
- OOS PF in these windows is below 1.0 for every combination tested
- The full-dataset PF (1.26–1.37 for tight-grid combos) confirms the strategy is historically profitable but not stationarily so

This pattern — strong full-dataset PF, weak WFO — is the signature of a regime-dependent strategy running out-of-regime in the test period. The cure is regime detection, not parameter optimization.

### 5e. Polygon WebSocket: backoff not disable

Decision was to implement exponential backoff (5s → 300s) rather than silently stopping reconnection on `auth_failed`. Rationale: if the Polygon plan is upgraded to include WS, the connection will auto-recover without a code change. The cost is one brief error burst per 5 minutes, which is acceptable. The initial commit `840ee01` had disabled retry entirely; `7555188` reverted that to proper backoff. The backoff version is the correct long-term behavior.

### 5f. RV filter: empirical evidence real, WFO unmeasurable at current frequency

The 36-trade empirical split (PF 2.54 vs 2.06) is not confirmed false — the mechanism is plausible. However, it cannot be validated by the existing WFO framework because 1-month OOS windows at SMA(50,200) frequency generate too few filtered trades for `p_edge` to be meaningful. This is a **measurement problem, not a hypothesis problem.** The filter is neither enabled nor discarded — it is deferred to live trade accumulation. See `MES_RV_FILTER_ANALYSIS_2026-05-06.md` for full analysis.
