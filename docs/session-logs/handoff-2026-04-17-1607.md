### 6.2 Task 2 — delete rather than comment-out
- Handoff doc was untracked, so no `git revert` needed. Truncated via Python-line-slice rather than `sed` for reliable handling of trailing whitespace + Unicode content.
- **Alternative rejected:** comment-out with `<!-- -->`. Rejected because the feedback memory says "remove", not "quarantine".

### 6.3 Task 3 — explicit channel allowlist, incremental `--after 7d`
- Hardcoded two channel IDs (`general` + `market-updates`) rather than iterating all 40+ channels. Rationale: T2.1 investigation proved agents only consume `discord_corey_commentary`, which is sourced from those two channels. Wider export wastes bandwidth + risks Discord rate limiting.
- Chose 7-day `--after` lookback — long enough to catch a missed daily run, short enough to keep per-invocation <5 MB after the initial catch-up.
- Cron at **02:00 America/Chicago** — after all US sessions close, before morning-brief at 06:30.
- **DCE install deferred to user action** — I don't silently install third-party Windows binaries. Path is overridable via `DCE_CLI_PATH` env var so the default is a suggestion, not a constraint.

### 6.4 Task 4 — client_id=7 for smoke
- Engine uses `client_id=1`. Smoke uses `client_id=7` — any distinct integer would work; 7 chosen for memorability. Prevents the smoke from kicking the engine off its IB socket.
- **Tiered exit codes** (2=no listener, 3=auth, 4=qualify, 5=place, 6=fill-timeout, 7=close) so CI / ops can distinguish operator errors from execution-path regressions. Non-zero doesn't just mean "failed" — it tells you which hop failed.
- **No CI wiring** — this script needs a live Gateway + real account; tagged as manual in docstring.

### 6.5 Unplanned — RL health schema rename
- Chose to make `/strategies/rl/health` **match the dashboard and tests** (new `*_available` names + `ready` roll-up), rather than update dashboard/tests to match the old endpoint. Rationale: dashboard was already written against the new names (the existing renderer expected `gymnasium_available`), so the endpoint was the laggard. Fixing the endpoint fixes both consumers in one change.
- Dropped the bare `gymnasium` and `stable_baselines3` fields entirely. Grep showed no other consumers. If future consumers appear, they'll fail fast rather than silently see stale names.

### 6.6 Unplanned — timeout bumps 5/10 → 15/20
- Chose 15s for urllib, 20s for requests. Reason: engine's observed worst-case response under full-suite load was ~10-12s (from pm2 logs), so 15s is ~1.3x the p99 observed latency. 20s on the per-test `requests` helpers gives headroom for slower endpoints (RL model evaluation, etc.) without masking true hangs.
- **Alternative rejected:** raise engine throughput. Correct long-term fix but out of scope — would require investigating the scheduler-job-contention issue mentioned in §5.2 item 3.
