- **Primary method**: `async def call(self, model: str, system: str, messages: list[dict], max_tokens: int = 1024, agent_name: str = "unknown", temperature: float = 0.7, allow_fallback: bool = True) -> LLMCallResult`
- **Return type**: `LLMCallResult` dataclass with fields `success`, `model`, `input_tokens`, `output_tokens`, `cost_usd`, `latency_ms`, `retries`, `content`, `error`
- **Retry logic**: 3 attempts with 1s→2s→4s exponential backoff on `RateLimitError`, `APIConnectionError`, `APIStatusError`
- **Fallback chain**: `claude-opus-4-6` → `claude-sonnet-4-6` → `claude-haiku-4-5-20251001` → None (configurable via `allow_fallback`)
- **Cost tracking**: SQLite at `data/llm_costs.db` via `CostTracker` class
- **Cost constants** (`COST_PER_MTOK`): Opus $15/$75, Sonnet $3/$15, Haiku $0.80/$4 per MTok

This interface informed the `AdvisorClient` design — specifically that advisor consultations should use `llm.call(model="claude-opus-4-6", system=..., messages=[...], max_tokens=600, temperature=0.2, agent_name="advisor_debate")`.

Wrote `engine/analytics/ic_ensemble.py` in a single `Write` call. Final file is **323 lines** (confirmed via `wc -l`). Structure:

```
"""..module docstring explaining Information Coefficient weighting.."""

from __future__ import annotations
import logging, sqlite3
from datetime import datetime, timedelta, timezone
from pathlib import Path
from typing import Dict, List, Optional, Tuple

logger = logging.getLogger(__name__)

# Try scipy, fall back to manual
try:
    from scipy.stats import spearmanr
    _HAS_SCIPY = True
except Exception:
    _HAS_SCIPY = False

__all__ = ["ICWeightedEnsemble"]

# Constants
_DEFAULT_DB_PATH = Path(__file__).resolve().parent.parent / "data" / "agent_feedback.db"
DEFAULT_AGENTS: Tuple[str, ...] = ("technical", "news", "social", "fundamental", "corey")
MIN_TRADES_FOR_IC = 5
DEFAULT_WINDOW_DAYS = 30

class ICWeightedEnsemble:
    def __init__(self, db_path=None, agents=None, window_days=30, min_trades=5)

    # Data fetch
    def _fetch_signals_and_pnl(self, agent_name) -> List[Tuple[float, float]]

    # Spearman (scipy preferred, manual fallback)
    @staticmethod
    def _manual_spearman(x, y) -> float
    def compute_ic(self, agent_name) -> float

    # Ensemble weights + consensus
    def get_ensemble_weights(self, agents=None) -> Dict[str, float]
    def weighted_consensus(self, analyst_reports, signal_key="signal") -> float

    # Diagnostics
    def get_ic_summary(self) -> Dict[str, float]
    def describe(self) -> Dict[str, object]
```

Key design details:
- **Column existence check**: `_fetch_signals_and_pnl` uses `PRAGMA table_info(trade_outcomes)` to verify the signal column exists BEFORE querying, preventing crashes on schema drift
- **NaN handling**: scipy's `spearmanr` returns `nan` on zero-variance inputs — explicit `ic != ic` NaN check with fallback to 0.0
- **Tie-handling in manual Spearman**: uses average-ranks-for-ties algorithm matching scipy default
- **Window query**: `WHERE timestamp >= ? AND {signal_col} IS NOT NULL AND pnl_usd IS NOT NULL` — filters NULLs at the SQL layer

```python
@staticmethod
def _manual_spearman(x: List[float], y: List[float]) -> float
```
Manual Spearman rank correlation when scipy is unavailable. Algorithm:
1. If `len(x) < 2` or `len(x) != len(y)`: return 0.0 (degenerate)
2. Compute ranks for x and y using AVERAGE RANKS FOR TIES (matches scipy default)
3. Compute Pearson correlation of the ranks
4. If either denominator is zero (constant vectors): return 0.0

Tie-handling is done in the inner `_rank` function:
```python
def _rank(values):
    indexed = sorted(enumerate(values), key=lambda p: p[1])
    ranks = [0.0] * n
    i = 0
    while i < n:
        j = i
        while j + 1 < n and indexed[j + 1][1] == indexed[i][1]:
            j += 1
        avg_rank = (i + j) / 2.0 + 1.0
        for k in range(i, j + 1):
            ranks[indexed[k][0]] = avg_rank
        i = j + 1
    return ranks
```

Verified to produce `0.9999999999999998` for perfect correlation and `-0.9999999999999998` for anti-correlation (floating-point precision limits prevent exact 1.0/-1.0).

                    model, agent_name, len(original), len(compressed),

            # Apply compressed version to the outgoing message
            last_msg["content"] = compressed
            user_content = compressed

    # ...existing retry loop...

    # NEW: Cache the successful response
    if proxy is not None and user_content is not None and result.success:

## 8 — Key Decisions Made

### 8.1 — Architectural decisions

#### D1: Complementary token-optimization layers
**Context**: `engine/utils/token_optimizer.py` already exists (untracked, from prior session) with Anthropic-specific primitives: `add_prompt_cache` (wraps system prompts in cache_control blocks), `select_model` (routes supporting analysts to Haiku on weak signals), `compress_analyst_report` (prunes low-IC agent context).
**Decision**: Build `token_proxy.py` as a COMPLEMENTARY module rather than replacing `token_optimizer.py`. Different layers:
- `token_optimizer.py` → **construction layer**: called when building the prompt (system block wrapping, model routing, context pruning)
- `token_proxy.py` → **transport layer**: called when sending the prompt (whitespace compression, response caching, trimming)
**Rationale**: Either can be swapped out independently. They operate on different aspects of the token cost problem. Both can run on the same prompt — you'd call `token_optimizer.add_prompt_cache(system)` first, then `token_proxy.compress_prompt(user_message)` second.
**Risk**: Naming collision confusion. Mitigation: docstrings in both files cross-reference each other.

#### D2: Graceful degradation over raising
**Context**: `AdvisorClient` is called from critical pipeline paths (debate tiebreak, trader refinement). If it raises, the whole pipeline crashes.
**Decision**: `AdvisorClient` NEVER raises on failure. Every `consult_*` method wraps the LLM call in `try/except Exception` and returns a valid `AdvisorVerdict` / `AdvisorRefinement` with `source="fallback"` and `consulted=False`.
**Rationale**: Callers use `result.consulted` as the branching condition, making integration strictly additive. If the advisor is unavailable, the pipeline falls through to its existing logic (e.g., INCONCLUSIVE → HOLD) rather than crashing.
**Risk**: Silent failures could hide advisor bugs. Mitigation: Every failure path logs at `warning` or `info` level with the exception details.

#### D3: Lazy LLM client loading with dual import paths
**Context**: The engine sometimes runs with `sys.path.insert(0, 'engine')` and sometimes without. Import paths differ based on entry point.
**Decision**: `AdvisorClient._try_lazy_load_llm` tries `from llm.client import JarvisLLMClient` FIRST (assumes `engine/` is on path), then falls back to `from engine.llm.client import JarvisLLMClient` (assumes working from project root). Also checks `ANTHROPIC_API_KEY` env var before construction.
**Rationale**: Module-level side-effect-free imports. Construction happens lazily on first use, so import-time errors don't crash the client.
**Risk**: If both import paths fail, the advisor silently becomes unavailable. Mitigation: `logger.info` on the "JarvisLLMClient not importable" path so failures are traceable.

#### D4: Reuse existing `trade_outcomes` schema for IC ensemble
**Context**: `AgentFeedbackTracker` already has a SQLite DB at `engine/data/agent_feedback.db` with a `trade_outcomes` table containing per-agent signal columns and `pnl_usd`.
**Decision**: `ICWeightedEnsemble` READS from this existing table instead of creating a separate IC tracking DB.
**Rationale**: Closes the IC feedback loop without new infrastructure. Schema already has the columns IC needs (`{agent}_signal` + `pnl_usd` + `timestamp`). The `PRAGMA table_info` check before querying prevents crashes on schema drift.
**Risk**: If the schema changes (columns renamed, table dropped), IC silently falls back to equal weights. Mitigation: `describe()` method exposes `db_exists` and `ics` values for dashboard visibility.

#### D5: scipy-preferred with manual Spearman fallback
**Context**: scipy is not a guaranteed dependency in the engine's venv.
**Decision**: `ICWeightedEnsemble` imports scipy in a `try/except`, sets `_HAS_SCIPY` flag. `compute_ic` uses scipy when available, manual Spearman implementation otherwise.
**Rationale**: Matches the "optional dependency" pattern used elsewhere in the codebase. Manual implementation is verified against edge cases (+1.0 perfect, -1.0 anti, 0.0 zero-variance).
**Risk**: Manual implementation is O(n log n) due to sorting — same asymptotic as scipy but with Python-level constants. For typical trade history sizes (<10K rows per agent), this is not a concern.

#### D6: Thread-safe singleton with double-checked locking
**Context**: JARVIS pipeline runs Stage 1 analysts under `asyncio.gather`, which means multiple concurrent calls to `get_token_proxy()` can race during first-init.
**Decision**: Use a module-level `threading.Lock` + double-checked locking pattern. Fast path: `if _global_proxy is not None: return _global_proxy`. Safe path: acquire lock, re-check, construct if needed.
**Rationale**: Standard Python idiom for thread-safe lazy init. The fast path has no lock contention after the first call.
**Risk**: asyncio and threading interact awkwardly; if a pipeline uses `asyncio.to_thread` to wrap the proxy call, the `threading.Lock` semantics are still correct (it's not an `asyncio.Lock`).
