## 6. Key decisions made — architectural choices, parameter values, tradeoffs

### Brier loop (Task 1)

| Decision | Choice | Rationale |
|---|---|---|
| Blend formula | Convex: `signal × (α·(1+IC) + (1-α)·brier_mult_centered)` | Linear, reviewable, regression-safe (α=1 ≡ pure IC). Matches `strategy-synthesis.md:40` intent. |
| `BRIER_BLEND_ALPHA` | **0.5** (symmetric) | Module constant, not config — tuneable in a follow-up. Symmetric = no prior that IC > Brier or vice versa. |
| Env-var gate | `BRIER_CALIBRATION_ENABLED=false` default | Dark-ship until `trade_outcomes` has ≥5 rows per agent. Flip to `true` once warmup occurs. |
| Close-time hook location | `PortfolioTracker.close_trade` + `close_paper_trade` (NOT the 5 open call sites) | All 5 call sites funnel through these 2 close methods. Mirrors existing `process_trade_outcome` hook. |
| Signal persistence | Extend existing `strategy_params` JSON blob | Already `TEXT` JSON in migration 001 — **zero schema migrations required**. |
| DB concurrency | Left as-is | Two separate SQLite files (`jarvis_trader.db` + `agent_feedback.db`). Contention near-zero at current trade frequency. WAL is a follow-up if needed. |
| Mock-scope in tests | Monkeypatch `engine.agents.debate._brier_tracker_instance` directly | DebateOrchestrator doesn't own the singleton (matches IC pattern). Constructor injection would drift from existing code. |

### Dual-module-path gotcha (learned during task 1 test debugging)

When `engine/` is on sys.path AND the repo root is on sys.path, `from engine.analytics.X import Y` and `from analytics.X import Y` produce **two distinct `sys.modules` entries**. Monkeypatching one does not affect the other. Tests must patch **both** `analytics.X` (short path) AND `engine.analytics.X` (absolute path) to cover both import styles. This cost ~2 test-fix iterations before the pattern was clear.

### OpenClaw secret storage (Task 4)

| Decision | Choice |
|---|---|
| Storage location | `/root/.openclaw/gateway.systemd.env` (mode 600) |
| Config reference | Env-ref object: `{"source":"env","provider":"openai","id":"OPENAI_API_KEY"}` |
| Rotation surface | 1 file (env file) instead of N config files |
| Allowlist mechanism | `OPENCLAW_SERVICE_MANAGED_ENV_KEYS` passes through only the names listed |

### Discord ingest regex (Task 5 bug fix)

Chose: `r"\[(\d+)\](?:\s*\([^)]*\))?\.json$"` — tolerates any parenthetical suffix (not just DCE's `(after ...)` form), future-proofing against other DCE flags that might emit suffixes.

Alternative rejected: rename files after export to strip the suffix. Rejected because it adds a file-system-mutation step that could partially fail and leave inconsistent state.
