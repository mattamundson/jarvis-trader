## 6. Key decisions (this session)

| Decision | Choice | Rationale |
|---------|--------|-----------|
| **Regex form for the widening** | `r"\[(\d+)\](?:\s*\([^)]*\))?\.json$"` | Non-capturing group `(?:...)` preserves `match.group(1)` as the channel-ID (no call-site change). `\s*` (zero-or-more) also handles the no-space `[ID](after...)` form DCE could emit. `[^)]*` is a negated-class, which halts at the first `)` — prevents catastrophic backtracking and correctly declines to match nested parens (Python `re` has no recursion support anyway, so refusing is safer than mis-matching). |
| **Commit scope** | Exactly one file: `engine/discord/parser.py` | Project rule (`~/.claude/rules/workflow.md`): "Never `git add -A` blindly — 1,450+ uncommitted GMS changes exist, triage carefully." Explicit-path add keeps the 95 untracked + 7 unrelated tracked-modified files out. |
| **Commit type prefix** | `fix(discord):` | Conventional commits. Recent branch history uses `fix:`, `feat:`, `chore:`, `docs:`, `refactor:`, `test:`. The change is a bug fix, scoped to the discord subtree. |
| **Commit message body** | Multi-line HEREDOC with *why* (DCE emits this filename shape) before *what* (regex widened) | Project rule (`~/.claude/rules/commits.md`-style): messages focus on *why*, not *what*. HEREDOC preserves hard line breaks. |
| **Test authoring** | **Deferred, not added this session** | Plan explicitly marked tests as "NOT part of this plan." User approved the plan. Follow-up flagged in §7. |
| **Caller audit of `extract_channel_id`** | **Deferred, not performed this session** | Same rationale — plan scoped to the commit, not an audit. Follow-up flagged in §7. |
| **Verification breadth** | 6 cases, not 3 | Plan originally listed 3 cases. Expanded to 6 at execution time to cover: space/no-space between `]` and `(`, nested parens, and two negative-control filenames. All 6 passed. More-is-better when verification is cheap. |
