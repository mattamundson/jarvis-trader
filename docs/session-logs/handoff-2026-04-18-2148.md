## 6. Key decisions made — architectural choices, parameter values, tradeoffs

### Scheduler safety (`engine/utils/scheduler_safety.py`)

- **Wrapper, not replacement.** APScheduler is already wired into `engine/main.py`; a
  full scheduler replacement would be a 4-week rewrite. Instead, wrap async callables
  and register the wrapper with APScheduler. Cost: callers must opt-in. Benefit: zero
  risk of regressing existing jobs.
- **Deterministic stagger.** Offsets come from `hashlib.md5(job_id).digest()[:4]` mod
  `spread_minutes`. Same input → same output forever. Guarantees no reshuffle on restart.
- **Default spread: 5 minutes.** Wide enough to break a 4-cron collision; narrow enough
  that a "20:05 EOD snapshot" still runs in the 20:05–20:09 window (well before market
  auction close at 21:00 UTC).
- **Dedupe records timestamp BEFORE call, not after.** Prevents a long-running job from
  allowing a simultaneous re-entry during its own execution window. Trade-off: if the
  job crashes, the next run waits out the dedupe window. That's the right default.
- **Quiet-hours default to `None, None`.** "No quiet hours" is the safe default — nothing
  goes silent unexpectedly if the env vars are unset/malformed.

### Cross-modal fallback (`engine/notifications/supervisor_fallback.py`)

- **Refusal detector is precision-tuned, not recall-tuned.** The regex requires a refusal
  verb like `help / assist / provide / comply / analyze` *immediately after* "can't" /
  "won't" — otherwise legitimate trade prose like "pattern can't be confirmed" would
  false-positive. Tested with 10 positive and 7 negative phrases.
- **Three outcome classes in `FallbackResult.source`:** `primary`, `fallback:refusal`,
  `fallback:error`, `both_failed`. `both_failed` stashes the fallback exception as
  `.value`. Caller inspects `.source` to decide whether to surface the result or escalate.
- **Refusal detection is pluggable.** The default stringifies and regex-matches, but
  callers with structured `LLMResult.content` objects pass a custom detector. Demonstrated
  in `test_try_with_fallback_structured_response_via_custom_detector`.

### SEPA trend template (`engine/analytics/sepa_trend_template.py`)

- **Returns `SEPAResult` dataclass with per-criterion fields, not a boolean list.** Makes
  debate-stage citation easy: "c6 failed: only 8% above 52wk low (need 30%)". The
  original sepa-strategy skill returned a boolean list; this port is an ergonomic upgrade.
- **Criterion default parameters match Minervini canonical values.** 50/150/200 SMA;
  30% above 52wk low; within 25% of 52wk high; RS ≥ 70. All tunable via kwargs for
  shorter-timeframe futures where calendar-weeks-of-data is the constraint.
- **Score is `passed / evaluated`, not `passed / 8`.** A 60-bar series that can only
  evaluate criterion 5 gets `score = 1.0` if c5 passes, not `0.125`. This keeps the score
  interpretable on short series without penalizing data insufficiency.
- **Relative-strength is a calibrated mapping, not a true IBD replica.** IBD's RS uses
  weighted 3/6/9/12-month composites; we use a single-lookback ratio mapped via
  `(1+close_ret)/(1+bench_ret)` → percentile, calibrated so 1.20 ratio → ~80. This is
  explicit in the module docstring as "intentionally coarse — a regime signal, not an
  IBD replica."
- **Benchmark is optional.** When `benchmark_close=None`, criterion 8 is skipped (None,
  not False) and is NOT counted in `evaluated_count`. Futures use cases (MCL/MNQ without
  a clean benchmark) don't get penalized.
