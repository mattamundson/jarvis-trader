## 6. KEY DECISIONS MADE

### Pine Script Compatibility Rules (canonical — apply to all future JARVIS_*.pine)
1. **NO `color.*` namespace** — use hex literals only. 8-digit for transparency, 6-digit for opaque.
   - `color.new(color.cyan, 20)` → `#00FFFFCC`
   - `color.new(color.teal, 50)` → `#00808080`
   - `color.new(color.blue, 60)` → `#2196F366`
   - `color.new(color.red, 60)` → `#FF525266`
   - `color.new(color.white, 15)` → `#FFFFFFD9`
   - `color.new(color.gray, 60)` → `#787B8666`
   - `color.new(color.gray, 50)` → `#787B8680`
   - `color.new(color.gray, 20)` → `#787B86CC`
   - `color.new(color.navy, 20)` → `#000080CC`
   - `color.new(color.black, 70)` → `#0000004D`
   - `color.new(color.black, 80)` → `#00000033`
   - `color.new(color.lime, 0)` → `#00E676FF`
   - `color.new(color.yellow, 0)` → `#FFEB3BFF`
   - `color.new(color.orange, 0)` → `#FF9800FF`
   - `color.new(color.red, 0)` → `#FF5252FF`
   - `color.new(color.cyan, 0)` → `#00FFFFFF`
   - `color.white` → `#FFFFFF`
   - `color.black` → `#000000`
2. **NO multi-line ternary/additive expressions** — collapse to single lines.
3. **NO function definitions inside `if` blocks** — always define at global scope; the conditional body only contains function CALLS.
4. **NO type annotations on variable declarations** (`color c_foo = ...` fails) — let Pine infer.
5. **Keep `//@version=5`** (v6 warning is severity 4 = warning only, not blocking).
