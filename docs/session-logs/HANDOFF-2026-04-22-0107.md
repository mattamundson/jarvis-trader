### 2.1 New files authored by this session

#### `engine/backtest/meanrev_signals.py` (217 lines, commit `29606ea`)

**Purpose**: Bollinger + RSI mean-reversion signal generator. First strategy module in the P1.1 arc of the roadmap (MCL-targeted mean-reversion candidate).

**Top-level exports:**
- `MEANREV_PARAMS: dict[str, dict]` — symbol → default params registry. Currently only `"MCL"`.
- `generate_bollinger_rsi_signals(df, bb_period=20, bb_std=2.0, rsi_period=14, rsi_long=30.0, rsi_short=70.0, stop_atr_mult=1.5) -> pd.DataFrame` — main entry point.
- `get_meanrev_params(symbol: str) -> dict | None` — case-insensitive lookup from the registry.
- Internal: `_wilder_atr`, `_wilder_rsi`.

**Key implementation details (traps for future readers):**

1. **Wilder RSI with proper NaN warmup**: The initial implementation used `rsi.where(avg_loss > 0, 100.0)` which incorrectly fired on NaN (because `NaN > 0` returns False, triggering the where replacement). The fix — caught during test-driven development by `test_wilder_rsi_warmup_is_nan` — uses `rsi.mask(avg_loss == 0.0, 100.0)`, which only fires when avg_loss is literally zero (monotonic-up series) and preserves NaN during warmup.

2. **Warmup guard in entry logic**: `warm = sma.notna() & rsi.notna() & atr.notna()`, then `long_cond = long_cond & warm`. Without this, the first 20 bars can produce bogus entries against NaN band edges.

3. **Conflict guard**: `conflict = long_cond & short_cond; long_cond &= ~conflict; short_cond &= ~conflict` — belt-and-suspenders for an impossible case (can't close both above upper and below lower band), but cheap.

4. **Exit signal is symmetric (midband cross either direction)**: `exit_cond = (crossed_up_through_mid | crossed_down_through_mid) & warm`. The column doesn't carry per-trade direction. Downstream backtester applies direction-aware semantics. Matches the pattern used by `breakout_signals.py` re-entry exit.

5. **Target ladder**: target_1 = midband (primary reversion target), target_2 = midband ± 0.5 × band_width, target_3 = opposite band (max reversion). SHORT targets mirror LONG.

**Why the params default to MCL-tuned values**: per the per-symbol decision memo (commit `c4a1ef1` and `project_per_symbol_strategy_decision.md`), MCL was flagged as a mean-reversion candidate rather than trend-following. This module is step 1 in the re-derivation.

**Why this module failed smoke** (the important part): vanilla BB+RSI on MCL 1h in a trend-biased period (2024–2026 oil bull run) produces 55% stops vs 44% midband reversions — the stops fire faster than the reversions complete. Without a regime filter to gate mean-reversion on range-bound conditions only, the strategy takes losses during trend days and has no compensating asymmetric payoff.

- `BREAKOUT_PARAMS: dict[str, dict]` — symbol → defaults. Only `"MNQ"` so far.
- `generate_donchian_breakout_signals(df, donchian_period=20, vol_ma_period=20, vol_mult=1.0, stop_atr_mult=2.0) -> pd.DataFrame`
- `get_breakout_params(symbol)` — same pattern as `get_meanrev_params`.
- Internal: `_wilder_atr` (shared pattern).

**Key design choices:**

1. **`shift(1)` on rolling max/min**: `donchian_high = high.rolling(N).max().shift(1)`. Without the shift, every new-high bar satisfies `close > donchian_high` (because the bar's own high is in the rolling window). The shift excludes the current bar from its own channel. This is the single most important correctness detail in the module.

2. **Volume gate with `vol_mult=0` disable**: `if vol_mult <= 0: vol_ok = pd.Series(True, index=df.index)` — lets ablated testing (compare filtered vs unfiltered) without special-casing.

3. **Warmup guard** on all four inputs (donchian_high, donchian_low, atr, vol_ma).

4. **Symmetric re-entry exit**: `exit_cond = (close <= donchian_high) & (close >= donchian_low) & warm`. This says "price is currently inside the prior-bar channel." For a LONG entry (broke above), this means "fell below donchian_high" = exit. For a SHORT entry (broke below), this means "rose above donchian_low" = exit. The column is direction-agnostic; the backtester handles per-trade semantics.

5. **Targets: 3/5/7 × ATR** matching `trend_signals.py` convention so mixed-strategy portfolios have consistent target ladders.

**Contract multiplier note**: the module emits point-level prices/stops/targets. The `scripts/mnq_breakout_emit_results.py` script multiplies by $2/pt when producing the validator input. A proper future refactor would promote this multiplier to `backtest/contract_specs.py` and have the emitter look it up by symbol.

**The new helper:**
```python
def _wait_for_chart_state(
    self,
    expected_symbol: Optional[str] = None,
    expected_resolution: Optional[str] = None,
    max_wait: float = 3.0,
) -> bool:
    """Poll `tv state` until reported symbol/resolution match what we set."""
    deadline = time.monotonic() + max_wait
    interval = 0.1
    while time.monotonic() < deadline:
        time.sleep(interval)
        state = self._get_state()
        if state is None:
            interval = min(interval * 1.5, 0.4)
            continue
        sym_ok = (expected_symbol is None) or (state.get("symbol") == expected_symbol)
        res_ok = (expected_resolution is None) or (state.get("resolution") == expected_resolution)
        if sym_ok and res_ok:
            return True
        interval = min(interval * 1.5, 0.4)
    return False
```

**Expected behavior change:**
- Fast chart (repaints in 150ms): poll returns True after ~250ms (100ms wait + 150ms probe) — beats the old 600ms floor by ~350ms.
- Medium chart (~600ms): returns True around the 600–800ms mark — comparable to old behavior.
- Heavy chart (~3s+): falls through with a warning instead of silently racing `tv ohlcv` against a still-stale chart.
- Extreme chart (~11s): still fails — but logs warning, falls through, lets next-tier data source (IBKR/Polygon/CSV) take over.

## §6. Key decisions made — architectural choices, params, tradeoffs

### 6.1 P1.1 did NOT advance to gate v2 battery

**Decision**: After smoke showed PF 0.855 (no edge), halted at P1.1 step 3.

**Alternatives considered**:
- Run gate v2 anyway to generate a "documented FAIL" — rejected as waste (known to fail PF ≥ 1.10 floor).
- Tune params to find a better config — rejected as premature optimization without regime filter.
- Discard the module entirely — rejected because the infrastructure (Wilder RSI/ATR, column contract, test harness) is reusable.

**Rationale**: gate v2 battery takes 5-10 min of compute. On a known-loser signal, running it teaches nothing new. Saving the "why it failed" to memory (trend-chop signature, 55% stops vs 44% reversions) is more valuable than a FAIL verdict.

**Tradeoff**: we lose the automated verdict file. But the memory file captures the same diagnostic detail with richer context.

### 6.2 P1.2 chose Donchian breakout over alternatives

**Decision**: Donchian(N) + volume confirmation as the first MNQ breakout candidate.

**Alternatives considered**:
- **Opening-range breakout (ORB)** — break of first 30-60min RTH range. Rejected for first pass because it requires session/calendar filters and has more moving parts. Good second-pass candidate.
- **Multi-timeframe breakout** — break on 1h confirmed by 4h direction. Rejected because aux-resampler would double the module scope and we wanted a clean first-pass baseline.
- **Bollinger Band squeeze breakout** — price inside tight bands → wait for expansion → enter in direction. Rejected because MCL had just failed with Bollinger-based logic; switching to breakout via the same primitive obscures the direction signal.

**Rationale**: Donchian is the canonical momentum-breakout primitive, textbook-simple, symmetric by default, and requires only OHLCV. Easy baseline to beat or iterate from.

**Tradeoff**: may have missed a better fit (ORB in particular). But the module contract is identical across breakout variants, so P1.2-v2 can add ORB on top at negligible cost.

### 6.3 Default parameters selected

#### `meanrev_signals.py` MCL defaults:
- `bb_period=20, bb_std=2.0` — textbook Bollinger on 1h bar periodicity
- `rsi_period=14, rsi_long=30.0, rsi_short=70.0` — textbook Wilder RSI oversold/overbought
- `stop_atr_mult=1.5` — TIGHTER than the 2.0 on MES SMA. Rationale: mean-rev accepts smaller wins (reverting to midband, not riding a trend), so stops should be smaller too. If stops are as wide as a trend strategy's, every false-mean-rev trade takes a full 2×ATR loss.

#### `breakout_signals.py` MNQ defaults:
- `donchian_period=20` — textbook
- `vol_ma_period=20, vol_mult=1.0` — soft volume gate ("at least average"). Chose 1.0 as the baseline to run ablation against 0 (no filter) and 1.5 (stronger filter).
- `stop_atr_mult=2.0` — MATCHES MES SMA trend. Breakouts need wider stops to survive the initial pullback that typically follows a real breakout.

#### `signal_scanner.py` delay default:
- `initial_delay_seconds=60` — long enough for uvicorn to bind and `/health` to respond before 4 concurrent pipeline runs spawn. Tested empirically: after 60s the event loop is quiet, agent init is mostly complete, and the first scan starts with minimal contention.
- Configurable via `SCANNER_INITIAL_DELAY_SECONDS` env var. Tests pass `initial_delay_seconds=0` to avoid waiting.

#### `_wait_for_chart_state(max_wait=3.0)`:
- 3.0s cap: observed `tv state` latency 150-300ms → 3s allows 5-8 probes. Heavy charts (gamma overlay stack) can take ~11s; those fail the poll and fall through with a warning. Falling through to next data tier (IBKR/Polygon/CSV) is better than silently fetching wrong-symbol bars.

#### `MNQ_DOLLARS_PER_POINT = 2.0` in emitter:
- MNQ = Micro NQ = 1/10 of NQ. NQ is $20/pt. MNQ is $2/pt.
- Hardcoded pending migration to contract_specs.py.

### 7.5 — P1.8 full fix: decouple scanner / heavy-init from uvicorn lifespan (MEDIUM, infra)

**Context**: the 60s delay I added in §2 is a band-aid. The real fix is architectural — the lifespan should bind uvicorn to the port FIRST, then kick off heavy init (scanner, RL model load, agent warmup) as background tasks that do not block the event loop during the first inbound request.

**Current lifespan shape** (`engine/main.py` lifespan function):
```
async with lifespan:
  await init_db()
  await init_safety_layer()
  rl_agent = load_rl_model()        # BLOCKS ~40s
  scanner = SignalScanner(...)      # starts immediately
  scanner_task = asyncio.create_task(scanner.start())
  scheduler.start()                 # BLOCKS ~5s on cron hydration
  yield
```

**Proposed shape**:
```
async with lifespan:
  await init_db()                   # fast, required for any endpoint
  await init_safety_layer()         # fast, required for /safety/*
  yield                             # uvicorn binds here; /health works
  # Post-yield: heavy init in background
  asyncio.create_task(_deferred_init(app))
```

Where `_deferred_init` runs RL load + scanner + scheduler in a named task, and tracks completion via `app.state.deferred_init_done`. `/health` gets a new field `heavy_init_ready: bool` so monitoring can distinguish "port bound, partial service" from "fully warm".

**Complications**:
- FastAPI's lifespan contract is "run to completion before yielding"; moving init past yield is unusual. Confirm with a dry run.
- The scanner currently assumes the agent registry is populated; deferred init must serialize scanner-start AFTER agent-start. Use `asyncio.Event` flags, not sleep.
- Some endpoints (pipeline/run) need scanner and scheduler to be live. Return 503 with "service warming" if called before `heavy_init_ready`.

**Expected payoff**: `/health` responds in <2s after `pm2 restart`. `restart_engine.ps1` timeout can drop from 360s back to something more sensible (e.g. 30s for bind + separate polling on `heavy_init_ready`).

**Timing**: ~3-4 hours to design + implement + test + verify. NOT a single-session task.
