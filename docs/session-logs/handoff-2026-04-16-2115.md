## 6. Key decisions made — architectural choices, parameter values, tradeoffs

### Brier interpretation for signals ∈ [-1, 1]

**Decision**: Use `confidence = |signal|`, `correct = (sign(signal) == sign(pnl))`, `brier_i = (confidence - correct)²`.

**Alternative considered**: Sigmoid mapping `p_win = σ(k · signal)` then `brier = (p_win - outcome)²`. Rejected because it introduces a free parameter `k` and the polymarket-toolkit source treats the raw score as a probability directly.

**Tradeoff**: Our formulation cannot distinguish "signal +0.3" from "signal -0.3" if both produce a losing trade — both register as confidence 0.3, correct=0 → brier 0.09. That's fine for calibration purposes.

### Neutral sentinel = 0.25

**Decision**: Insufficient-data Brier returns 0.25, not 0.0.

**Why**: 0.0 means "perfect calibration" — a completely uninformed agent would be unfairly boosted if it shared that value. 0.25 is the Brier of a pure coin-flip predictor (p=0.5 against binary outcome). Distinct from both perfect (0.0) and max-wrong (1.0).

### Weight formula: `w_i ∝ 1 / (brier_i + ε)` with ε = 0.01

**Decision**: Inverse-plus-epsilon, then normalize to sum to 1.0.

**Alternative**: Linear mapping `w = 1 - brier`. Rejected because it keeps wrong agents at positive weight (brier 0.9 → weight 0.1).

**Tradeoff**: Inverse gives unbounded weight to perfect (brier 0.0) agents — that's why ε is there. ε = 0.01 means a perfectly calibrated agent gets weight ~100× a median (brier 0.25) one. Feels right; can tune down to 0.05 if concentration is too extreme.

### Zero-signal trades excluded from Brier computation

**Decision**: `WHERE agent_signal != 0 AND pnl_usd != 0` in the SQL query.

**Why**: A trade where the agent had no opinion (signal = 0) shouldn't dilute its Brier either way. If we included zero-signal trades, confidence = 0, so `brier_i = (0 - correct)²` which is 0 or 1 purely based on the trade outcome — adding noise unrelated to the agent's calibration.

### BRIER_NEUTRAL placed at module level

**Decision**: `BRIER_NEUTRAL = 0.25` as a module-level constant, not a class attribute.

**Why**: Makes it importable for test assertions (`assert brier == BRIER_NEUTRAL`) and documents the sentinel's meaning outside the class context.

### Archive stale Paperclip files, don't delete

**Decision**: `git mv` into `.claude-stale/paperclip-agents/` rather than `git rm`.

**Why**: Auto-mode constraint: "Anything that deletes data still needs explicit user confirmation." Archive is fully reversible (`git mv .claude-stale/paperclip-agents/foo.md .claude/agents/foo.md`).

**Tradeoff**: `.claude-stale/` is untracked in git; if user wants it committed as a historical record, add it to git next session.

### Did NOT wire Brier into debate.py

**Decision**: Ship Brier as an importable class, leave wiring for a separate decision-path diff.

**Why**: `.claude/rules/safety.md` and project convention keep decision-path changes isolated. Brier-wiring changes agent weights, which changes trades, which changes money. One focused PR per behavior change.

### Matched CLAUDE.md numbers to code, not to session memory

**Decision**: When `safety.md` said `-2% daily` but `MEMORY.md` said `-10% daily`, I trusted `safety.md` (cites actual config constant).

**Why**: Code is authoritative. Memory rots. This is the "verify before citing" rule from the auto-memory system.
