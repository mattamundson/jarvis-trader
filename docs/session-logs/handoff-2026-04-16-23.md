## Lessons captured

1. **Test fakes ≠ production dataclass** — the PATCH guard passed all unit tests green while silently accepting inverted stops in production, because test `_FakeTrade.side = "buy"` didn't match real `Trade.action`. Fixes: read `.action or .side` in the guard, add regression test that uses `.action` explicitly.
2. **Windows vs POSIX `os.execvp`** — on POSIX it's a PID-preserving process replacement; on Windows it's a PID-changing spawn. Anything that relies on `execvp` in a Windows process-supervisor context (PM2, systemd-stub, etc.) will loop. Use in-process calls or `subprocess.run()`.
3. **Band calibration for data-source audit** — for detecting wrong-instrument contamination, the signal is *orders of magnitude* (futures $5000 vs stock $1-$15), not *percentage over ceiling*. First iteration produced 25 false positives because bands were calibrated on 2024 highs, not 2026 highs. Widen when the flagged max is just over ceiling.
4. **30-orphan process accumulation was not a bind bug** — it was a PID-tracking bug. Each execvp created a new process; PM2 thought guardian died; PM2 restarted; new guardian spawned new uvicorn; repeat. The 30 orphans were 30 successful uvicorn launches that PM2 just wasn't aware of.
